# chemd v0.1 Product Prototype Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the remaining `chemd v0.1` product-prototype work after the recent boundary-alignment fixes, focusing on the missing chemistry backend and the incomplete molecule/reaction interaction loops.

**Architecture:** Keep `chemd` as the document-semantic core and make the chemistry backend a stable external capability layer. `render-profile` must become the single source of truth for render constraints, `renderer-svg` remains fallback-only, and the web app should converge on one shared DTO/store model that supports both molecule and reaction flows.

**Tech Stack:** TypeScript, Next.js 15, React 19, Vitest, Python Flask chem-service, RDKit, Ketcher, external OCR providers, Pandoc

---

## Current State Snapshot

### Already Completed
- Default web surface is now `Editor + Preview`; `Tree` is no longer mounted on the default page.
- `reaction.conditions` is already part of the v0.1 contract across AST, parser, renderer, and docs.
- Molecule preview hydration exists through `/api/chem/render`.
- Molecule OCR and molecule structure-save routes already exist as minimal shells.
- `services/chem-service` already exposes fallback `/ocr`, `/normalize`, `/render`, and `/structure` endpoints.

### Still In Scope For v0.1
- RDKit-backed normalize/render as the formal molecule rendering path.
- OCR provider integration for molecule and reaction.
- Molecule Ketcher loop hardening onto the final backend contract.
- Reaction preview hydration, OCR write-back, and edit/save loop.
- Render-constraint consolidation that removes drift between `render-profile`, backend DTOs, and fallback renderer.

### Out Of Scope For This Plan
- `Tree` formalization.
- `training-export` and any v0.2 training pipeline work.
- Unrelated refactors that do not directly support the v0.1 product mainline.

### Known Gaps Confirmed In Code
- `apps/web/src/server/chem/dto.ts` and `apps/web/src/server/chem/structure-store.ts` are still molecule-only.
- There are no `/api/chem/reaction/ocr`, `/api/chem/reaction/render`, or `/api/chem/reaction/save` routes yet.
- `apps/web/src/features/chem-preview/hooks/useRenderedPreview.ts` only upgrades molecule graphics and only emits `chemd:edit-molecule`.
- `apps/web/src/features/structure-editor/components/KetcherFrame.tsx` is still a placeholder shell.
- `services/chem-service/app.py` still returns fallback OCR/normalize/render responses and has no reaction-specific endpoints.
- `packages/renderer-svg/src/index.ts` still re-sanitizes render adapter options locally.
