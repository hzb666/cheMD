# chemd v0.1 Product Prototype Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the `chemd v0.1` product prototype as an `Editor + Preview` experience with molecule and reaction support, external OCR provider integration, RDKit-backed rendering/normalization, and Ketcher editing loops.

**Architecture:** Keep `chemd` itself as the document-semantic core: parser, resolver, compiler, render-profile, and document write-back remain owned by this repo. Treat OCR, normalization, depiction, and graphical editing as integrated external capabilities behind stable API and DTO boundaries. Keep `renderer-svg` as fallback only, and move the default preview path to the backend render service.

**Tech Stack:** TypeScript, Next.js 15, React 19, Vitest, Python Flask chem-service, RDKit, Ketcher, external OCR providers, Pandoc

---

## Current State Snapshot

### In Scope For This Plan
- `v0.1` includes `Editor + Preview`, molecule mainline, reaction mainline, OCR provider integration, RDKit-backed normalize/render, Ketcher editing, and blocking refactors that directly support those flows.
- `Tree` is experimental only and must not remain on the default v0.1 surface.
- `training-export` is v0.2 and must not block this plan.

### Already Completed
- `packages/core`, `packages/parser`, `packages/resolver`, and `packages/compiler` already form a working document pipeline.
- `packages/render-profile` already supports built-in profiles, inheritance, fallback, overrides, and diagnostics.
- `packages/renderer-html`, `packages/renderer-json`, and `packages/renderer-docx` already provide preview/inspect/export outputs.
- `apps/web/src/app/api/chem/ocr/route.ts` already implements a molecule OCR route shape and stores normalized structure drafts.
- `apps/web/src/app/api/chem/normalize/route.ts`, `apps/web/src/app/api/chem/render/route.ts`, and `apps/web/src/app/api/chem/structure/save/route.ts` already exist for molecule-only chemistry operations.
- `apps/web/src/features/chem-preview/hooks/useRenderedPreview.ts` already hydrates molecule graphics through `/api/chem/render`.
- `apps/web/src/features/ocr/hooks/useImageOcr.ts` already performs molecule OCR upload and silent write-back into the document.
- `apps/web/src/features/structure-editor/components/KetcherDialog.tsx` and `KetcherFrame.tsx` already provide a minimal molecule edit shell.
- `services/chem-service/app.py` already provides a running fallback service with OCR, normalize, render, and short-term structure cache endpoints.

### Partially Completed
- `apps/web/src/app/page.tsx` already exposes OCR, preview, and Ketcher, but still mounts `DocumentTreePanel`, which is out of v0.1 scope.
- Molecule backend preview exists, but only via fallback Flask responses and molecule-only DTOs.
- Molecule Ketcher save exists, but depends on molecule-only DTOs and cache records.
- `renderer-svg` already produces fallback molecule and reaction graphics, but it still carries too much runtime sanitization responsibility that should live in `render-profile`.
- `services/chem-service` exists, but is still placeholder-only for OCR and RDKit behavior.

### Not Completed
- `packages/core/src/ast.ts` does not yet include `reaction.conditions`.
- `packages/parser/src/body/parse-body.ts` does not yet parse `conditions` as a reaction list field.
- `packages/resolver` does not yet validate `reaction.conditions` or any reaction-specific edit/write-back contract.
- `apps/web/src/server/chem/dto.ts` is molecule-only.
- `apps/web/src/server/chem/structure-store.ts` is molecule-only.
- There are no `/api/chem/reaction/ocr`, `/api/chem/reaction/render`, or `/api/chem/reaction/save` routes yet.
- `useRenderedPreview` only upgrades molecule graphics; reaction backend hydration is missing.
- There is no reaction OCR hook, no reaction edit button bridge, and no reaction Ketcher save loop.
- The OCR layer is still effectively coupled to a single molecule OCR shape; provider abstraction for molecule vs reaction is missing.
- RDKit-backed normalize/render is not yet implemented in the Python service.
