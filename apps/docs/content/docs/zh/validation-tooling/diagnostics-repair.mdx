## frontmatter 缺失字段

缺少 `id`、`title` 或 `date` 产生 `E_MISSING_REQUIRED_FRONTMATTER_KEY`。frontmatter 存在但字段为空字符串时，assigner 会生成无效值诊断。修复应补齐非空字符串，并保持 key 语法为小写字母开头。

```yaml
---
id: exp-main
title: Main experiment
date: 2026-04-24
---
```

## 非法日期

日期诊断分两层。`W_NON_ISO_FRONTMATTER_DATE` 表示格式未匹配 `YYYY-MM-DD`。`W_INVALID_FRONTMATTER_DATE_VALUE` 表示格式匹配但日历值无效，例如月份或日期超出范围。推荐使用完整日期，并把导入系统中的自由文本日期放入额外元数据字段。

## 非法块 ID

块 ID 必须匹配 `^[a-zA-Z][a-zA-Z0-9_-]*$`。非法 ID 产生 `E_INVALID_ID`。该规则适用于 `:::chemd #id`、`:::result #id`、`:::analysis #id`、`:::sample #id`、`:::artifact #id`、`:::procedure #id`、`:::observation #id` 和 `:::condition-varies #id`。

## 未知字段

字段不在对应 block 的允许集合内时产生 `W_UNKNOWN_FIELD`。parser 会丢弃未知字段。修复应优先使用已实现字段；补充型信息可放入 `notes`、`caption`、`conditions` 或项目自定义 frontmatter 标量。

示例：`:::result` 接收 `isolated_mass`，未实现 `mass` 字段。写成 `mass: 30 mg` 会产生 `W_UNKNOWN_FIELD`，并且结果节点不会保存该值。

## 空列表项

列表字段支持 `|` 与逗号分隔。连续分隔符、尾部分隔符和空字符串项产生 `E_INVALID_LIST_ITEM`。常见字段包含 `reactants`、`products`、`conditions`、`prev`、`artifacts`、`chemistry_features`、step `inputs`、step `outputs`、step `dependsOn` 和 event `evidence`。

## 未解析引用

resolver 对行内引用、对象字段引用、primary alias、模板参数引用和条件筛选 attempt 引用执行解析。未解析对象或字段产生 `W_UNRESOLVED_REFERENCE`。typechecker 对语义字段进一步执行目标类型检查，类型不匹配产生 `E_TYPED_REFERENCE_MISMATCH`。

引用修复路径：

- 检查目标对象 ID 是否存在。
- 检查 `@id.field` 中的字段是否为 AST 中真实字段。
- 检查 `primary_*` 是否指向存在对象。
- 检查 bare ID 是否需要改为 `@id`。
- 跨文档引用需要通过 `referenceContext` 或 `reactionRouteContext` 提供 external target。

## 重复 ID

对象 ID 重复产生 `E_DUPLICATE_ID`。模板名重复产生 `E_DUPLICATE_TEMPLATE`。semantic diff 只比较显式 ID 对象，因此重复 ID 会破坏后续 diff、graph 和 export 的稳定性。修复应给每个语义对象分配唯一 ID。

## 缺失必填字段

resolver 必填字段：

| 对象 | 必填字段 |
| --- | --- |
| molecule | `smiles` |
| reaction | `reactants`、`products` |
| analysis | `type_name`、`data` |
| TLC analysis | `type_name` |
| sample | `name` |
| artifact | `kind`、`path` |

analysis 的 `type` 字段在 AST 中保存为 `type_name`。TLC analysis 在 parser 中补入默认 `plate` 与 `visualization`，resolver 对 TLC 放宽 `data` 要求。

## 模板参数错误

模板诊断覆盖索引、展开和参数类型。`E_UNKNOWN_TEMPLATE` 表示 `:::use` 找不到模板。`E_TEMPLATE_PARAM_MISSING` 表示调用缺少必需参数。`E_TEMPLATE_PARAM_TYPE_MISMATCH` 表示 `ref<kind>` 或 `quantity<class>` 与传入值不匹配。`E_TEMPLATE_CYCLE` 表示模板递归。`E_TEMPLATE_EXPANSION_LIMIT` 表示展开深度超过 32 或展开节点超过 2000。

`ref<kind>` 支持 molecule、reaction、result、analysis、procedure、observation、sample、artifact 和 condition_varies。`quantity<class>` 支持 amount、mass、volume、temperature、time、pressure、concentration、equivalent 和 percent。

## primary 引用错误

primary 字段目标不存在产生 `E_INVALID_PRIMARY_REFERENCE`。行内 `@reaction.field` 等 alias 依赖对应 `primary_*`。修复方式为补齐目标对象、修正 primary ID、或将行内 alias 改为显式对象引用 `@id.field`。

## 类型检查诊断

typechecker 生成 v0.3 diagnostics。常见类型检查诊断：

| 诊断码 | 触发条件 |
| --- | --- |
| `E402` | percent 数量超出 0 到 100 |
| `E403` | 数量无法按目标 quantity class 解析 |
| `E306` | result `status` 不在 success、partial、failed、unknown 等 alias 内 |
| `E_TYPED_REFERENCE_MISMATCH` | 引用目标类型与字段要求不一致 |
| `E_RESULT_REACTION_CONFLICT` | result 与 linked reaction 的 yield、conversion 或 selectivity 不一致 |
| `E_STEP_INVALID_FAMILY` | step family 未在实现集合内 |
| `E_STEP_PARAM_MISSING` | family 必需参数缺失 |
| `E_STEP_PARAM_INVALID` | family 禁止的参数出现 |
| `E_STEP_ID_DUPLICATE` | 显式 step ID 重复 |
| `E_STEP_INVALID_REFERENCE` | `dependsOn` 指向不存在 step |
| `E_STEP_DEPENDENCY_CYCLE` | step dependency 形成循环 |
| `E_OBSERVATION_EVENT_INVALID_TYPE` | event type 未在实现集合内 |
| `E_OBSERVATION_LINKED_STEP_MISSING` | event 指向不存在 step |
| `W_REACTION_ROUTE_MISMATCH` | route 前驱关系路线不一致 |
| `E_REACTION_ROUTE_CYCLE` | reaction route 形成循环 |
| `W_REACTION_ROUTE_ORPHAN` | route 内存在孤立 reaction |

## quick fix 与 repair loop

当前 quick fix kind 包含 `apply_authoring_patch` 和 `insert_chemd_kind`。`insert_chemd_kind` 用于 `chemd` 类型推断相关诊断。`apply_authoring_patch` 携带 compiler input assistance 生成的安全修复建议。

`runChemdRepairLoop` 默认最多迭代 5 次。每轮编译、构建 diagnosis、应用 safe fixes、重新编译。停止原因包含 clean、max iterations、stalled 和 diagnosis status。`--write` 只在修复后 clean 且源码变化时写回。

## agent loop 诊断闭环

`runChemdAgentLoop` 在 deterministic repair loop 后调用外部 driver。driver 接收源码、诊断和迭代历史，并返回 `rewrite` 或 `stop`。停止原因包含 clean、max iterations、repair max iterations、repair stalled、agent stalled 和 diagnosis status。该流程用于自动修复无法由 quick fix 独立覆盖的输入问题。
