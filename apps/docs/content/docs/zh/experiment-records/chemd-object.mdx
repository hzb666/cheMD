## `kind: molecule`

`kind: molecule` 生成 `MoleculeNode`。molecule 表达化学身份：结构、名称、标识符、分子式和分子量。本次反应用量不属于 molecule；amount 与 equivalents 写在 reaction participant 上。

```md
:::chemd #mol-aryl
name: aryl bromide
smiles: Brc1ccccc1
role: substrate
formula: C6H5Br
:::
```

字段说明：

| 字段 | 语义 |
| --- | --- |
| `smiles` | 结构表达式 |
| `cas` | CAS registry string，当前实现只保存原值 |
| `inchi` | InChI 标识符 |
| `inchikey` | InChIKey 标识符 |
| `canonical_smiles` | canonical 结构字符串 |
| `name` | 使用者可读名称 |
| `role` | 使用者定义角色，如 substrate、reagent、product |
| `caption` | 渲染层说明文本 |
| `formula` | 分子式原文 |
| `mw` | 分子量文本 |
| `chemistry_features` | 扩展 feature 引用列表 |

## `kind: reaction`

`kind: reaction` 生成 `ReactionNode`。canonical 写法使用可重复的 `reactant` 和 `product`。`reac` 与 `prod` 是短别名。`reactants` 与 `products` 仍是简单列表别名，但结构化数量只能写在单数 participant 字段上。

```md
:::chemd #rxn-main
name: Suzuki coupling
reactant: @mat-aryl-lot-a | 1.00 mmol | 1.0 eq | limiting=true
reactant: @mol-boron | 1.5 eq
product: @mol-product
reagents: K2CO3
catalyst: Pd(PPh3)4
solvent: dioxane/water
temperature: 90 C
time: 12 h
atmosphere: nitrogen
yield: 82 %
:::
```

typechecker 会把 reaction participant 解析到 molecule、material 或 batch；校验 limiting reactant 边界；解析 `prev` 路线关系；解析 `temperature`、`time` 与 `pressure`；并归一化 `atmosphere`。

## 省略 `kind` 时的类型推断

parser 根据字段形状推断 `chemd` 块类型。participant 字段推断为 reaction；`smiles`、`cas`、`inchi`、`inchikey`、`canonical_smiles`、`formula` 或 `mw` 等身份字段推断为 molecule。无法稳定推断时产生 `W_CHEMD_KIND_AMBIGUOUS` error，并提供插入 `kind: molecule` 或 `kind: reaction` 的 quick fix。

冲突规则：

| 输入形态 | 诊断 |
| --- | --- |
| `kind: molecule` 且存在 reaction 形状字段 | `E_CHEMD_KIND_CONFLICT` |
| `kind: reaction` 且缺少 reaction 形状字段 | `E_CHEMD_KIND_CONFLICT` |
| `kind` 为空字符串或非法字符串 | `E_CHEMD_KIND_CONFLICT` |
| 省略 `kind` 且字段形态无法稳定推断 | `W_CHEMD_KIND_AMBIGUOUS` |

## molecule 字段手册

molecule 字段集合由 schema registry 固定。未知字段产生 `W_UNKNOWN_FIELD`，字段不会写入 AST。非字段正文可作为隐式 `smiles` 值读取；隐式值超过一行时产生 `W_INVALID_CHEMD_IMPLICIT_VALUE`。

typechecker 要求 molecule 有身份字段。没有身份字段产生 `E_MOLECULE_IDENTITY_MISSING`。molecule 上写 `amount` 或 `equivalents` 产生 `E_MOLECULE_REACTION_QUANTITY`。

## reaction 字段手册

reaction 字段集合由 schema registry 固定。可重复的单数 participant 字段是 canonical 写法；复数形式只作为简单列表别名。

| 字段 | 解析与语义 |
| --- | --- |
| `reactant` / `reac` | 可重复 reactant participant；支持引用、amount、equiv、mass、volume 和 `limiting=true` |
| `product` / `prod` | 可重复 product participant |
| `reactants` | 简单 reactant 引用/文本列表别名 |
| `products` | 简单 product 引用/文本列表别名 |
| `conditions` | 字符串列表，供渲染和导出使用 |
| `route` | 路线标签 |
| `prev` | reaction 前驱引用列表 |
| `reagents` | 原文字符串 |
| `catalyst` | 原文字符串 |
| `solvent` | 原文字符串，并参与 condition classifier |
| `temperature` | temperature 数量 |
| `time` | time 数量 |
| `pressure` | pressure 数量 |
| `atmosphere` | `nitrogen`、`argon`、`air`、`oxygen`、`inert` 或 extension |
| `yield` | AST 字符串，result 关系校验会与 result yield 比对 |
| `conversion` | AST 字符串，result 关系校验会与 result conversion 比对 |
| `selectivity` | AST 字符串，result 关系校验会与 result selectivity 比对 |
| `rxn_smiles` / `reaction_smiles` | 可选 reaction structure；显式值必须在 participant 身份可用时与其一致 |

`rxn_smiles` 可省略。当每个 participant 都解析到带 `smiles` 或 `canonical_smiles` 的 molecule 时，typed graph 可以从 participant 推断 reaction structure。如果显式值无法验证或与 participant 冲突，typechecker 会报告 interop error。

## Participant 引用写法

`reactant` 和 `product` 值以引用或文本开头。引用可写为 `@id`，也可写为 bare ID。typechecker 在本地对象索引或 external target index 中找到 bare ID 时会将其视为引用；未命中的 bare value 保留为 literal。

```md
reactant: @mat-aryl-lot-a | 1.00 mmol | 1.0 eq | limiting=true
reactant: @mol-boron | 1.5 eq
product: @mol-product
```

复数列表别名不能携带 amount 或 equivalent 这类结构化 participant 事实，否则产生 `E_REACTION_PARTICIPANT_SYNTAX`。尾部分隔符产生空列表项，诊断码为 `E_INVALID_LIST_ITEM`。

## `route` / `prev` 路线关系

`route` 保存路线名或路线 ID。`prev` 保存当前 reaction 的前驱 reaction 引用。typechecker 通过 `resolveReactionPrevReferences` 解析 `prev`，并结合 `reactionRouteContext` 支持跨文档 reaction。路线校验包含引用类型检查、路线名不一致检查、循环检查和 orphan 检查。

相关诊断：

| 诊断码 | 触发条件 |
| --- | --- |
| `E_TYPED_REFERENCE_MISMATCH` | `prev` 指向非 reaction 目标 |
| `W_REACTION_ROUTE_MISMATCH` | 前驱路线与当前路线不一致 |
| `E_REACTION_ROUTE_CYCLE` | reaction route 存在循环 |
| `W_REACTION_ROUTE_ORPHAN` | route 上存在无法连接的 reaction |

## `chemistry_features` 扩展引用

`chemistry_features` 由 `readChemistryFeatureRefs` 转换为 `chemistryFeatureRefs`。molecule 中的 feature kind 为 `molecule`，reaction 中的 feature kind 为 `reaction`。当前 parser 将这些 feature 标记为 `status: "available"`。该字段服务于后续扩展型化学特征、训练导出和外部知识图谱整合。

## 推荐实践示例

molecule 与 reaction 对象应写在下游 result、analysis、procedure、sample 和 artifact 之前。类型化关系使用 `@id`，路线关系显式写入 `route` 与 `prev`。

```md
:::chemd #mol-substrate
name: benzyl alcohol
smiles: OCc1ccccc1
role: substrate
:::

:::chemd #mol-product
name: benzaldehyde
smiles: O=Cc1ccccc1
role: product
:::

:::chemd #rxn-oxidation
name: benzyl alcohol oxidation
route: route-oxidation
reactant: @mol-substrate | 1.00 mmol | 1.0 eq | limiting=true
product: @mol-product
reagents: MnO2
solvent: CH2Cl2
temperature: 25 C
time: 4 h
yield: 81 %
:::
```
