下列清单汇总 Chemd 使用者可以直接使用的语言能力。你可以用它检查记录写法、验证文件，或选择合适的导出格式。

## 语言输入面

Chemd 接收 Markdown 正文、YAML frontmatter、`:::` 结构化块、模板块、列布局块、行内引用、行内化学表达式、行内代码和 Markdown 链接。支持的结构化块名称包含 `chemd`、`material`、`batch`、`result`、`analysis`、`artifact`、`sample`、`condition-varies`、`procedure`、`trace`、`observation`、`use` 和 `col`。`template` 使用 `bind`、`params`、`description` 和 `body` 头部字段。

未知结构化块产生 error 级 `W_UNKNOWN_BLOCK` 诊断。

## Frontmatter 特性

- 必需字段：`id`、`title`、`date`。
- 主对象字段：`primary_reaction`、`primary_result`、`primary_product`、`primary_sample`、`primary_molecule`、`primary_analysis`。
- 标签字段：`tags` 接受字符串数组。
- 渲染选择：`render_profile` 接受非空字符串，`render_overrides` 接受单层 path/value 映射。
- 额外元数据：接受标量值，保存到 `ChemdMeta`。
- 不支持的值形状：block scalar、隐式多行 scalar、非 `tags` 或 `render_overrides` 的嵌套结构、顶层非 mapping。

`render_overrides` 支持这些 path：`structure.bondLength`、`structure.bondLineWidth`、`structure.multipleBondOffset`、`structure.hashSpacing`、`structure.fontSize`、`structure.atomLabelPadding`、`structure.monochrome`、`structure.backgroundColor`、`reaction.arrowLength`、`reaction.componentGap`、`reaction.plusGap`、`reaction.showConditionsBelowArrow`、`export.imageFormat`、`export.margin`、`export.dpi`、`export.transparentBackground`。

## 行内语法特性

- `@id`：对象引用。
- `@id.field`：对象字段引用。
- `@reaction.field`、`@result.field`、`@product.field`、`@sample.field`、`@molecule.field`、`@analysis.field`：primary alias 字段引用。
- `@meta.field`：frontmatter 元数据引用。
- `@param.field`：模板参数字段引用。
- `:chem[...]`：行内化学表达式，空内容与跨行内容无效。
- Markdown 链接：安全 href 包含 `#`、`/`、`./`、`../`、scheme-free、`http`、`https` 和 `mailto`。含控制字符或不安全 scheme 的 href 产生 `W_UNSAFE_LINK_HREF`。

## 字段解析特性

字段行使用 `key: value`。key 以小写字母开头，后续可包含小写字母、数字和下划线。列表字段使用 `|` 或逗号分隔，空列表项产生 `E_INVALID_LIST_ITEM`。单行可用 `;;` 写入多个字段。块 ID 必须匹配 `^[a-zA-Z][a-zA-Z0-9_-]*$`。

默认列表字段包含 `reactants`、`products`、`reactant`、`product`、`reac`、`prod`、`conditions`、`params`。`chemd` 额外把 `prev` 作为列表字段。`sample` 把 `artifacts` 和 `chemistry_features` 作为列表字段。

## 结构化对象特性

- `:::chemd`：通过 `kind` 或字段形状生成 molecule 或 reaction。缺少 `kind` 时按 reaction participant 字段或 molecule identity 字段推断；无法稳定推断时产生 `W_CHEMD_KIND_AMBIGUOUS` error。
- molecule 字段：`smiles`、`canonical_smiles`、`cas`、`inchi`、`inchikey`、`name`、`role`、`caption`、`formula`、`mw`、`chemistry_features`。
- reaction 字段：`name`、`reactant`、`product`、`reac`、`prod`、`reactants`、`products`、`conditions`、`route`、`prev`、`reagents`、`catalyst`、`solvent`、`temperature`、`time`、`pressure`、`atmosphere`、`yield`、`conversion`、`selectivity`、`equation`、`rxn_smiles`、`reaction_smiles`、`caption`、`chemistry_features`。
- `:::material` 字段：`molecule`、`supplier`、`lot`、`purity`、`density`、`storage`、`notes`、`chemistry_features`。
- `:::batch` 字段：`source`、`molecule`、`state`、`mass`、`purity`、`artifacts`、`notes`、`chemistry_features`。
- `:::result` 字段：`status`、`yield`、`conversion`、`selectivity`、`isolated_mass`、`product_state`、`purity`、`notes`、`ref`、`reaction`、`product`。
- `:::analysis` 字段：`type`、`ref`、`time`、`eluent`、`plate`、`visualization`、`result`、`instrument`、`solvent`、`frequency`、`method`、`data`、`notes`、`artifact`、`artifacts`、`spectrum`、`lane`、`spot`、`mess`、`base`、`none`、`peak`、`ion`。
- `:::sample` 字段：`name`、`sample_id`、`batch`、`purity`、`supplier`、`notes`、`ref`、`derived_from`、`aliquot_of`、`batch_of`、`artifacts`、`chemistry_features`。
- `:::artifact` 字段：`kind`、`ref`、`path`、`checksum`、`instrument`、`notes`、`chemistry_features`。
- `:::condition-varies` 字段：`reaction`、`standard`、`factor`、`outcome`、`attempt`、`result`、`note`、`notes`，以及已声明的 attempt 字段。
- `:::procedure` 字段：`ref`、`reaction`、`evidence`，并接收 `step:` 行、嵌套 `:::step`，以及 `repeat`、`until`、`branch`、`parallel`、`wait`、`abort_if` 控制行。
- `:::trace` 字段：`plan` 和 `mode`，并接收手写 `event:` 行。
- `:::observation` 字段：`ref`，并接收 `event:` 行和嵌套 `:::event`。
- `:::col` 语法：列数来自 header 参数，例如 `:::col-2` 或 `:::col 2`；子项写作 `col:` 行，子项可包含 Markdown 或括号包裹的结构化内容。

## Resolver 与 Typechecker 特性

resolver 构建对象索引，检查重复 ID，解析行内引用，解析 primary alias，展开模板，校验必填字段。必填字段为 material `molecule`、batch `source`、analysis `type_name`、sample `name`、artifact `kind` 与 `path`。molecule identity 与 reaction participant 存在性由 typechecker 校验。

typechecker 构建 typed semantic graph、step graph、数量单位归一化、引用类型检查、结果关系检查、样品关系检查、reaction route 检查、reaction participant 化学计量检查和 observation 事件链接检查。数量单位覆盖 amount、mass、volume、temperature、time、pressure、concentration、equivalent、percent、rate、rpm 和 pH。percent 超出 0 到 100 产生 `E402`，无法解析数量或紧凑数字-单位语法产生 `E403`，单位大小写不规范产生 `W_QUANTITY_UNIT_CASING`。

## Procedure 与 Observation 特性

显式 step family 包含 `charge`、`add`、`transfer`、`mix`、`cool`、`heat`、`hold`、`purge`、`quench`、`extract`、`wash`、`separate_layers`、`filter`、`dry`、`concentrate`、`purify`、`sample`、`analyze`、`observe` 和 `store`。`purge` 在缺少 `atmosphere` 时默认使用 `nitrogen`。

显式 observation event type 包含 `color_change`、`precipitation`、`gas_evolution` 和 `phase_change`。事件可通过 `linkedStep` 或 `linked_step` 指向 step。缺失 step 目标产生 `E_OBSERVATION_LINKED_STEP_MISSING`。

## 模板特性

`:::template name` 支持 `params`、`bind`、`description` 和 body。参数类型支持 `string`、`ref<kind>` 和 `quantity<class>`。ref kind 支持 molecule、material、batch、reaction、result、analysis、procedure、observation、sample、artifact 和 condition_varies。quantity class 支持 amount、mass、volume、temperature、time、pressure、concentration、equivalent、percent、rate、rpm 和 pH。

模板展开最大深度为 32，最大展开节点数为 2000。循环产生 `E_TEMPLATE_CYCLE`，未知模板产生 `E_UNKNOWN_TEMPLATE`，缺参产生 `E_TEMPLATE_PARAM_MISSING`，类型不匹配产生 `E_TEMPLATE_PARAM_TYPE_MISMATCH`。

## 编译与导出特性

`compileChemd` 的主链路为 parse、resolve、typecheck、render profile resolution、runtime run plan、runtime preflight、LNF、training export、RAG export、training understanding、input assistance、input-assistance diagnostics、diagnosis、HTML、JSON 和 DOCX bridge。

CLI 命令包含 `validate`、`export`、`graph`、`diff`、`changed`、`fix` 和 `agent-loop`。`export` 格式包含 `json`、`lnf`、`rag`、`training` 和 `training-full`。`graph`、`diff`、`changed`、`fix` 和 `agent-loop` 的文本输出格式支持 `text` 与 `json`。
