---
title: 运行预检
description: Chemd runtime-lab 如何把编译后的步骤和控制流转成 run plan、preflight issue、人工确认或 adapter 门禁。
---

运行层不改变 Chemd 语法。它消费语言流水线产出的 canonical step graph 和 control graph，并为 dry run、human run、robot run 或 replay 准备 run plan。

## 运行输入

运行预检从 procedure step 开始。若后续 observation、artifact 或外部运行记录需要回指同一个操作，应保持 step ID 稳定。

```mdx
:::procedure #proc-runtime
step: cool | id=s-cool | target_temperature=-78 C
step: add | id=s-add | dependsOn=s-cool | reagent=n-BuLi
until: monitor-tlc | condition=@ana-tlc.result == complete | max_iterations=4 {
  step: analyze | id=s-tlc-check | type=tlc
}
wait: operator-approval | condition=operator.confirmed | timeout=30 min
step: analyze | id=s-tlc | type=tlc | dependsOn=s-add
:::
```

## Run Plan

`@chemd/runtime-lab` 暴露 `buildRunPlan`。plan ID 由 document ID 派生，形式为 `runplan::<documentId>`。

```ts
import { buildRunPlan, preflightRun } from "@chemd/runtime-lab";

const plan = buildRunPlan({
  documentId: "exp-runtime",
  stepGraph
});

const preflight = preflightRun(plan, {
  mode: "human-run",
  capabilities: ["cooling", "analytical_tlc"],
  adapters: [{ adapterId: "manual", supports: ["wait"], available: true }]
});
```

当 runtime diagnostic 中存在 error 级别诊断时，`preflight.blocking` 为 `true`。

run plan 包含 `steps`、`controls`、`controlStates` 和运行时诊断。`wait`、`until`、`branch`、`abort_if` 这类动态控制在 `controlStates` 中初始为 `waiting_adapter`，因为下一步取决于运行状态或操作者输入。

## 控制流预检

运行预检接收 `:::procedure` 生成的 control graph。`repeat` 已经展开为固定 step。`parallel` 会保留 path，并可能生成 `resource_conflict` issue。`until`、`branch`、`wait` 和 `abort_if` 需要运行状态、adapter 或操作者决策。

```md
:::procedure #proc-runtime-controls
reaction: @rxn-main
step: charge | id=s-charge | inputs=@mat-substrate | outputs=mixture-a

repeat: wash-cycle | count=2 {
  step: wash | solvent=brine | volume=10 mL
}

until: tlc-complete | condition=@ana-tlc.result == complete | max_iterations=4 {
  step: analyze | id=s-tlc-check | type=tlc
}

branch: temperature-response {
  case: overheated | condition=sensor.temperature > 80 C {
    step: cool | target_temperature=25 C
  }
  default: normal {
    step: hold | duration=10 min
  }
}

parallel: workup {
  path: organic {
    step: dry | medium=Na2SO4
  }
  path: aqueous {
    step: store | location=waste
  }
}

abort_if: unsafe-pressure | condition=sensor.pressure > 2 bar
:::
```

`robot-run` 要求每个 dynamic control 都有可用 adapter。`human-run` 仍会显示缺失 adapter 的提示，但面向操作者的门禁可以作为人工决策继续保留。

## 运行模式

运行模式有四种：

- `dry-run`：只规划和检查执行，不控制真实实验运行。
- `human-run`：面向人工执行，并暴露确认点。
- `robot-run`：要求所有 step family 都能被 runtime planner 识别。
- `replay-run`：回放已记录的运行状态或 trace。

## 能力要求

部分 step family 会引入能力要求：

| Step family | Capability |
| --- | --- |
| `cool` | `cooling` |
| `heat` | `heating` |
| `purge` | `inert_gas` |
| `filter` | `filtration` |
| `purify` | `chromatography` |
| `dry`, `concentrate` | `vacuum` |
| `analyze` 且 `type=tlc` | `analytical_tlc` |
| `analyze` 且 `type=nmr` | `nmr` |
| `analyze` 且 `type=hplc` | `hplc` |

缺失能力会生成 runtime preflight 诊断。

capability、confirmation strategy 和 safety tag 都来自 `@chemd/step-ontology` 的 StepFamily schema。runtime 包不应再维护一套独立 family map。

## CLI Preflight

面向使用者的运行检查通过 CLI：

```text
chemd preflight experiment.chemd --mode human-run --format text
chemd preflight experiment.chemd --mode robot-run --context lab.json --format json --dry-run
```

`--mode` 接受 `dry-run`、`human-run`、`robot-run` 和 `replay-run`。`--format` 接受 `text` 和 `json`。`--dry-run` 只表示报告不会触发真实执行，不会弱化诊断。

JSON report schema 为 `chemd-preflight/v0.1`，结构如下：

```json
{
  "schemaVersion": "chemd-preflight/v0.1",
  "dryRun": true,
  "filePath": "experiment.chemd",
  "mode": "robot-run",
  "preflight": {
    "blocking": true,
    "issues": [],
    "diagnostics": []
  }
}
```

## Context 文件

`--context lab.json` 提供实验室运行状态。该文件会覆盖默认 capabilities，并可包含 adapters、devices、inventory、environment 和 safety rules。

```json
{
  "capabilities": ["heating", "cooling", "analytical_tlc"],
  "devices": [
    { "capability": "heating", "min": 20, "max": 120, "unit": "C" }
  ],
  "inventory": {
    "materials": [
      { "id": "mat-substrate", "available": true, "hazards": ["acid"] },
      { "id": "mat-base", "available": false }
    ]
  },
  "adapters": [
    { "adapterId": "operator", "supports": ["wait", "abort_if"], "available": true }
  ],
  "safetyRules": [
    {
      "ruleId": "confirm-quench",
      "trigger": { "stepFamily": "quench" },
      "severity": "error",
      "requiresConfirmation": true,
      "message": "Quench requires operator confirmation."
    },
    {
      "ruleId": "acid-review",
      "trigger": { "materialHazard": "acid" },
      "severity": "warning",
      "requiresConfirmation": true,
      "message": "Acid handling requires review."
    },
    {
      "ruleId": "branch-review",
      "trigger": { "controlKind": "branch" },
      "severity": "warning",
      "message": "Branch controls require operator review."
    }
  ]
}
```

Safety rule 可按 `stepFamily`、`param`、`materialHazard` 或 `controlKind` 触发。`materialHazard` 会从 step 的 `inputs` 或 `materials` 中读取物料 ID，再与 `inventory.materials[].hazards` 匹配。

## Preflight Issues

runtime preflight 同时输出面向人的 `issues` 和 compiler 形状的 `diagnostics`。

| issue kind | diagnostic | 含义 |
| --- | --- | --- |
| `capability` | `E605` | 缺少必要 capability |
| `device_range` | `E_RUNTIME_DEVICE_RANGE` | temperature、pressure、rpm 或 rate 超出设备范围 |
| `inventory` | `E_RUNTIME_INVENTORY` | 所需输入物料不可用或过期 |
| `adapter` | `E_RUNTIME_ADAPTER` | robot-run 缺少运行时动作 adapter |
| `control` | `E_RUNTIME_CONTROL` | 动态 control 需要运行时决策 |
| `resource_conflict` | `E_RUNTIME_RESOURCE_CONFLICT` | `parallel` 需要资源冲突审查 |
| `safety` | `W_RUNTIME_SAFETY` | safety rule 或 safety tag 需要关注 |

error 级别 issue 会让 `preflight.blocking` 为 true，并让 CLI 返回退出码 1。只有 warning 时退出码仍为 0，但报告中会保留提示。

## 确认策略

runtime planner 会为每个 step 选择一种确认策略：

- `manual_required`：`add`、`quench`、`purge`、`heat`、`cool` 等高触达操作。
- `review_inferred`：由 lower 过程推断出的 step，或 lowering confidence 偏低的 step。
- `none`：不需要 runtime 确认门禁的 step。

这些策略属于运行时元数据，不改变 parser、resolver 或 typechecker 行为。

## 推荐实践示例

适合运行预检的 procedure 记录应使用显式 step ID、依赖链接，以及 runtime planner 已识别的 step family。

```md
:::procedure #proc-runtime-ready
reaction: @rxn-main
step: charge | id=s-charge | inputs=@mol-substrate | outputs=mixture-a
step: cool | id=s-cool | target_temperature=-78 C | dependsOn=s-charge
step: add | id=s-add | reagent=n-BuLi | dependsOn=s-cool
wait: operator-approval | condition=operator.confirmed | timeout=15 min
step: analyze | id=s-tlc | type=tlc | dependsOn=s-add
:::
```

在 `human-run` 模式下，该记录会为高触达操作生成确认点，并检查 cooling 与 TLC analysis capability。
