title: 归一化语义
description: Chemd typechecker 和 core helper 对反应条件、TLC 泳道、状态、分析类型、气氛与关系的归一化规则。
---

Chemd parser 保存使用者输入，typechecker 与 core helper 在后续阶段构建归一化语义。归一化结果用于 HTML、DOCX bridge、LNF、RAG、training export 和 graph index。

## 反应条件

Chemd 会对 reaction 条件执行轻量归一化。输入来自 reaction 的 `conditions`、`reagents`、`catalyst`、`solvent`、`temperature`、`time`、`pressure` 和 `atmosphere`。

| 字段 | 归一化行为 |
| --- | --- |
| `conditions` | 保留为 `conditions_text`，并作为候选条件池 |
| `solvent` | 识别 EtOH、MeOH、H2O、DCM、THF、MeCN、DMF、DMSO、toluene、EtOAc 等别名 |
| `catalyst` | 显式字段优先；未写时从 `conditions` 中匹配包含 catalyst 的文本 |
| `atmosphere` | 识别 N2、nitrogen、Ar、argon、air、O2、oxygen |
| `temperature` | 解析 `C`、`°C`、`K`、`F` |
| `time` | 解析 `h`、`hr`、`hrs`、`min`、`mins` |
| `pressure` | 解析 `bar`、`atm`、`psi` |
| `reagents` | 显式 `reagents` 按 `|` 拆分，并追加未被其他条件消费的 `conditions` 项 |

```md
:::chemd #rxn-main
kind: reaction
reactants: @mol-a
products: @mol-b
conditions: MeCN | 60 C | 3 h | N2 | Pd catalyst | K2CO3
solvent: MeCN
temperature: 60 C
time: 3 h
atmosphere: N2
:::
```

最佳实践为显式填写结构化条件字段，并把自由文本条件放在 `conditions` 中作为补充。显式字段优先级更高，归一化结果更稳定。

## 结果状态

result `status` 由 `normalizeStatus` 归一化为 `success`、`partial`、`failed` 或 `unknown`。

| 输入 | 归一化 |
| --- | --- |
| `success`、`complete`、`completed`、`done` | `success` |
| `partial`、`partial_conversion` | `partial` |
| `failed`、`fail` | `failed` |
| `unknown` | `unknown` |

其他值产生 `E306`，并归一化为 `unknown`。

## 分析类型

analysis `type` 在 AST 中保存为 `type_name`。typechecker 识别以下分析类型别名：

| 输入 | 归一化 |
| --- | --- |
| `tlc` | `tlc` |
| `nmr` | `nmr` |
| `hplc` | `hplc` |
| `lcms`、`lc-ms` | `lcms` |
| `gcms`、`gc-ms` | `gcms` |

未命中别名的值作为 extension 保留。该设计允许使用者记录项目专用分析方法。

## 反应气氛

reaction `atmosphere` 在 typechecker 中归一化为 known 或 extension。

| 输入 | 归一化 |
| --- | --- |
| `n2`、`nitrogen` | `nitrogen` |
| `ar`、`argon` | `argon` |
| `air` | `air` |
| `o2`、`oxygen` | `oxygen` |
| `inert` | `inert` |

其他值作为 extension 保留，不产生诊断。

## TLC 泳道

TLC 归一化会按数字顺序读取 `p1`、`p2`、`p3` 等字段。lane 文本使用 `|` 拆分为 lane label 与 spot 项。

支持 lane label：

| label 形态 | lane_role |
| --- | --- |
| `sm`、`starting material` | `starting_material` |
| `pd`、`product` | `product` |
| `int`、`intermediate` | `intermediate` |
| `rxn`、`reaction` | `reaction` |
| 数字 | `trial` |
| 其他 | `custom` |

支持 spot 与区域：

| 写法 | 语义 |
| --- | --- |
| `0.52` | Rf spot |
| `0.52 ^3(4)` | 上箭头形状，size rank 3，intensity rank 4 |
| `0.31 v2` | 下箭头形状，size rank 2 |
| `base` | lane 有 baseline spot |
| `none` | lane 无 spot |
| `mess`、`mess(0.45)` | 拖尾或混乱区域 |

rank 值被限制在 1 到 5。无法识别的 spot 项会被忽略。

```md
:::analysis #ana-tlc
type: tlc
ref: rxn-main
time: 2 h
eluent: petroleum ether/ethyl acetate 5:1
p1: sm 0.62 | base
p2: rxn 0.31 ^3(4) | mess(0.55) | sm 0.62 v1
p3: product 0.30
:::
```

## Result 与 Reaction 关系

typechecker 使用 result 的 `reaction` 字段；缺少该字段时使用 `ref`。目标必须是 reaction。`product` 必须指向 molecule。

当 result 关联 reaction 后，typechecker 检查：

- `product` 是否出现在 linked reaction 的 `products` 列表中。
- result 的 `yield`、`conversion`、`selectivity` 是否与 linked reaction 同名字段一致。

product 不属于 reaction product 时产生 `E_TYPED_REFERENCE_MISMATCH`。指标不一致时产生 `E_RESULT_REACTION_CONFLICT`。

## Sample 关系

sample 关系字段包含 `ref`、`derived_from`、`aliquot_of` 和 `batch_of`。`aliquot_of` 与 `batch_of` 必须指向 sample。`derived_from` 与 `ref` 可解析为对象引用或保留为 literal。

```md
:::sample #sample-aliquot-a
name: aliquot A
aliquot_of: @sample-parent
purity: 97 %
:::
```

## 最佳实践

归一化语义依赖结构化字段。使用者应优先把可校验事实写入字段，把叙述性补充写入 `notes`、`caption` 或 Markdown 正文。
