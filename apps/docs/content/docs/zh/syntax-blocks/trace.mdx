---
title: '`:::trace` 运行追踪块'
description: '`:::trace` 记录 procedure plan 的运行事件，不改写 procedure 或 result。'
---

`:::trace` 用于保存作者写入或外部导入的运行事件。它必须关联到一个 `:::procedure` plan，并根据编译后的 step graph 与 control graph 校验。

trace 数据不修改源码中的 procedure、reaction 或 result。它只记录真实执行、回放或审计事实，供后续工具比较“作者意图”和“运行事实”。

## 语法

```md
:::trace #run-main
plan: @proc-main
mode: human-run
event: run_started | at=2026-05-20T10:00:00Z
event: step_started | step=s-charge | at=2026-05-20T10:01:00Z
event: step_completed | step=s-charge | at=2026-05-20T10:03:00Z
event: control_entered | control=operator-approval | at=2026-05-20T10:04:00Z
event: deviation_recorded | step=s-heat | field=temperature | expected=40 C | actual=45 C
:::
```

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `plan` | 是 | procedure 引用；`@proc-main` 和 `proc-main` 都可接受 |
| `mode` | 否 | `dry-run`、`human-run`、`robot-run` 或 `replay-run` |
| `event` | 否 | trace event 的子行语法 |

块内普通正文会保留为 markdown children。正文可以记录导入来源、操作者备注或外部 run ID，但机器可读事件应使用 `event:`。

## Event 行

格式为 `event: type | key=value | key=value`。

常用结构键如下：

| 键 | 含义 |
| --- | --- |
| `id`、`event_id` | 可选 event 标识 |
| `at` | ISO datetime；有时间的事件必须保持单调递增 |
| `step`、`stepId`、`step_id` | 关联 procedure plan 中的 step ID |
| `control`、`controlId`、`control_id` | 关联 procedure plan 中的 control ID |
| `artifact` | artifact 引用 |
| `analysis` | analysis 引用 |
| `result` | result 引用 |

其他 `key=value` 会作为 event payload 保留。例如 `deviation_recorded` 要求 `field`、`expected` 和 `actual`；`resource_consumed` 要求 `material` 或 `resource`，并且必须有 `amount`。

## Event 类型

当前支持的 runtime trace event 类型包括：

```text
run_started, run_completed, run_aborted,
step_started, step_completed, step_failed, step_skipped,
control_entered, control_completed, control_blocked, control_aborted,
operator_action, confirmation_granted, manual_override,
artifact_generated, observation_recorded,
measurement_recorded, analysis_recorded,
deviation_recorded, diagnostic_recorded, diagnostic_emitted,
resource_consumed
```

typechecker 会校验引用和 payload 要求。step 与 control 引用只在 `plan` 指向的 procedure 内有效；即使另一个 procedure 中存在同名或其他 step ID，也不能被当前 trace 引用。runtime replay 会把事件投影到 `LabState` 的 step state、control state、artifact、observation、diagnostic、deviation count 和回放 trace stream。

## 推荐实践

trace ID 应和 procedure ID 分开。procedure 描述意图，trace 描述运行事实。

```md
:::procedure #proc-main
step: charge | id=s-charge | inputs=@mat-substrate | outputs=mixture-a
wait: operator-approval | condition=operator.confirmed | timeout=30 min
step: heat | id=s-heat | temperature=40 C | duration=30 min | dependsOn=s-charge,operator-approval
:::

:::trace #run-2026-05-20-a
plan: @proc-main
mode: human-run
event: run_started | at=2026-05-20T09:00:00Z
event: step_started | step=s-charge | at=2026-05-20T09:01:00Z
event: step_completed | step=s-charge | at=2026-05-20T09:03:00Z
event: control_entered | control=operator-approval | at=2026-05-20T09:04:00Z
event: control_completed | control=operator-approval | at=2026-05-20T09:05:00Z
event: step_started | step=s-heat | at=2026-05-20T09:06:00Z
event: step_completed | step=s-heat | at=2026-05-20T09:36:00Z
event: run_completed | at=2026-05-20T09:37:00Z
:::
```

## 诊断

| 诊断码 | 条件 |
| --- | --- |
| `E_TRACE_PLAN_REFERENCE` | `plan` 未引用 procedure |
| `E_TRACE_EVENT_TIME` | `at` 不是 ISO datetime，或时间不单调 |
| `E_TRACE_EVENT_REFERENCE` | event 引用了未知 step、control、artifact、analysis 或 result |
| `E_TRACE_EVENT_PAYLOAD` | event type 缺少必需 payload 字段 |
| `W_TRACE_STEP_STATE` | `step_completed` 出现在对应 `step_started` 前；在 `robot-run` 或 `replay-run` 中升级为 error |
