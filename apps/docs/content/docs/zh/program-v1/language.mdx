`chemd/program-v1` 是 breaking-change language contract。它不为 legacy
Markdown-first 模型保留 parser fallback。

## 定位

一个 `.chemd` 文件就是一个 module 和一个 program。

```text
.chemd source
  -> chemd/program-v1 module
  -> declarations
  -> compiler facts, rendering inputs, exports, storage records, IDE symbols
```

Program declarations 是语义事实。Molecules、reactions、results、
procedures、samples、analyses、observations、traces 和 agent audit
records 只有在源码中存在对应 declaration 时才成立。

Markdown 只作为文档进入编译器：

- `///` 行级 doc comment
- `/*md ... */` Markdown documentation region

文档可以渲染，也可以进入 narrative RAG chunks，但不能创建 molecule、
reaction、result、procedure 或 agent facts。

## 移除的语法

Program v1 移除以下语法，并且不做兼容 lowering：

- `---` YAML frontmatter
- `:::chemd`、`:::procedure`、`:::result`、`:::analysis` 等 fenced blocks
- `:::template` 与 `:::use`
- `:::col`、`:::col-2`、`:::col-N`
- 从 Markdown body text 推断语义事实
- core compiler path 中的 `.chemd.md` 兼容

Legacy source 必须先改写成 program syntax 才能编译。

## Source Example

```text
module exp_golden_suzuki_screen

import shared_solvents as solvents from "./shared-solvents.chemd"

meta {
  id: "exp-golden-suzuki-screen"
  title: "Suzuki coupling solvent screen"
  date: 2026-04-24
  primary_reaction: @rxn_var1
  primary_result: @res_var1
  tags: ["suzuki", "screen"]
}

/*md
# Suzuki coupling solvent screen

This region is documentation. It is renderable and retrievable, but it does
not create molecule, reaction, result, procedure, or agent facts.
*/

molecule mol_aryl {
  name: "aryl bromide"
  smiles: "Brc1ccccc1"
  role: substrate
}

reaction rxn_var1 {
  reactants: [@mol_aryl]
  products: ["biphenyl product"]
  solvent: "MeCN"
  temperature: 40 C
  time: 2 h
}

result res_var1 for @rxn_var1 {
  status: success
  yield: 78%
}

procedure proc_var1 for @rxn_var1 {
  step charge = charge(inputs: [@mol_aryl])
  step heat = heat(temperature: 40 C, duration: 2 h, depends_on: [charge])
}
```

## Grammar Sketch

```text
program          := module_decl import_decl* meta_decl top_decl*
module_decl      := doc_comment* "module" ident
import_decl      := doc_comment* "import" ident ("as" ident)? "from" string
meta_decl        := doc_comment* "meta" block
top_decl         := doc_comment* declaration
declaration      := molecule_decl | material_decl | batch_decl | reaction_decl
                  | result_decl | analysis_decl | sample_decl | artifact_decl
                  | condition_screen_decl | procedure_decl | observation_decl
                  | trace_decl | agent_run_decl
reference        := "@" reference_target ("." ident)?
reference_target := ident | ident "." ident | ident "#" ident
```

Reference forms：

- `@rxn_var1` 解析为本地 declaration。
- `@rxn_var1.yield` 解析为本地 declaration field。
- `@module_name.rxn_var1` 解析为 module-qualified declaration。
- `@external_doc#rxn_step_01` 解析为 resolver context 提供的外部文档 anchor。

## Diagnostics

Legacy syntax diagnostics 是 fatal parser diagnostics。它们说明移除原因并终止编译，
不是 recovery branches。

| Code | Trigger |
| --- | --- |
| `E_LEGACY_FRONTMATTER_REMOVED` | Source starts YAML frontmatter with `---` |
| `E_LEGACY_FENCED_BLOCK_REMOVED` | Source contains a legacy `:::` block |
| `E_LEGACY_TEMPLATE_REMOVED` | Source contains `:::template`, `:::use`, or legacy template parameters |
| `E_LEGACY_COLUMN_LAYOUT_REMOVED` | Source contains `:::col`, `:::col-2`, `:::col-N`, or column layout syntax |

## IDE Contract

Language service 基于 program declarations 工作，而不是 Markdown blocks。Outline、
hover、completion、diagnostics、source ranges 和 patch targets 必须使用
declaration IDs、field paths、doc comment IDs、procedure step IDs 和 agent run IDs。
