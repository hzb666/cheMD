Program-first exports 把 declarations 视为语义事实。Markdown 只作为 doc
comments 附着的文档存在。

## Export Model

- `ChemdProgramDocument`
- `module`、`imports`、`meta` 和 typed declarations
- 附着到 file、module、declaration、field、procedure step 和 agent statement 的 doc comments
- renderer/exporter program payloads
- `source_layer.program`、`source_layer.meta`、`source_layer.declarations` 和 `source_layer.doc_comments`
- `semantic_layer.documentation_blocks`

`compileChemd(source, options)` 解析 program source，并返回 program-first 编译 payloads。

## Compile Pipeline

```text
source program
  -> parseChemdProgram()
  -> resolveProgram()
  -> typecheckProgram()
  -> resolveRenderProfileWithDiagnostics()
  -> buildRunPlan()
  -> preflightRun()
  -> buildCanonicalLnf()
  -> exportTrainingRecordFromProgram()
  -> buildRagExportFromTrainingRecord()
  -> buildTrainingUnderstandingFromRecord()
  -> buildProgramRenderDocument()
  -> renderHtml()
  -> renderJson()
  -> renderDocxBridge()
```

`parseChemdProgram()` 产出 `ChemdProgramDocument`。Renderers 消费
`ProgramRenderDocument`，而不是 raw AST unions。Storage 消费已编译的 export
payloads，不解析 source。

## Training、RAG 与 LNF

Training export version 是 `chemd-training-export/v0.3`。

`ProgramSourceLayerV1` 记录 module、meta、declarations、doc comments、
diagnostics 和 audit-only field markers。

`ProgramSemanticLayerV1` 记录 `documentation_blocks`。Documentation blocks
的 `fact_status` 是 `"narrative_only"`。

RAG chunks 保留 truth boundaries：

```ts
export type ProgramRagChunkKind =
  | "semantic_fact"
  | "narrative_doc"
  | "agent_audit"
  | "runtime_trace";

export interface ProgramRagChunkV1 {
  chunk_id: string;
  chunk_kind: ProgramRagChunkKind;
  truth_source: "declaration" | "doc_comment" | "agent_run" | "trace";
  fact_status: "source_truth" | "narrative_only" | "audit_only" | "runtime_only";
  source_ids: string[];
  text: string;
  citations: ProgramCitationV1[];
  metadata?: Record<string, unknown>;
}
```

LNF version 是 `chemd-lnf/v1.0`。它使用 source completeness metrics：
declaration count、documentation count、unresolved reference count、incomplete
declaration count 和 agent audit run count。

## Storage and Desktop

`@chemd/storage-postgres` 保持 pure：不打开数据库连接、不读取环境变量、不调用
compiler、不生成 embeddings、不执行 SQL、不解析 source。Program storage 会新增
declarations、doc comments、symbol references、RAG citations、reaction graph
nodes/edges 和 agent audit records。

Desktop IDE 和 Graph/RAG surfaces 消费 program-level identities：

- module name
- declaration ID and kind
- declaration field
- doc comment ID
- procedure step ID
- agent run, tool call, patch, and decision IDs
- trace and runtime event IDs

Source jumps 目标是 `declaration:<id>`、`field:<id>.<field>`、`doc:<id>`、
`agent:<run_id>`、`agent_patch:<patch_id>` 或 `trace:<trace_id>`，并通过
program-level identities 解析。
