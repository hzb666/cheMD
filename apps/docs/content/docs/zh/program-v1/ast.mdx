`chemd-program-ast/v1` 是 `.chemd` program source 的 public AST contract。
下游 packages 使用这个形状完成 semantic validation、rendering、exports、
diagnostics、language service data 和 storage。

## Program Document

```ts
export interface ChemdProgramDocument extends SourceMappedNode {
  type: "program_document";
  schemaVersion: "chemd-program-ast/v1";
  sourceLanguage: "chemd/program-v1";
  module: ChemdModuleDeclaration;
  meta: ChemdMetaDeclaration;
  imports: ChemdImportDeclaration[];
  declarations: ChemdDeclaration[];
  docs: ChemdDocComment[];
  diagnostics: Diagnostic[];
  source?: string;
  renderSelection?: RenderSelection;
}
```

`module` 和 `meta` 必填。`declarations` 只包含 semantic declarations。
`docs` 包含导出的 Markdown documentation comments，不包含顶层 Markdown body nodes。

## Declarations

```ts
export type ChemdDeclaration =
  | MoleculeDeclaration
  | MaterialDeclaration
  | BatchDeclaration
  | ReactionDeclaration
  | ResultDeclaration
  | AnalysisDeclaration
  | SampleDeclaration
  | ArtifactDeclaration
  | ConditionScreenDeclaration
  | ProcedureDeclaration
  | ObservationDeclaration
  | TraceDeclaration
  | AgentRunDeclaration;
```

Declaration IDs 在 module 内唯一。Resolver 负责生成 `qualifiedId`，例如
`exp_golden_suzuki_screen.rxn_var1`。

## Values

Parser 负责分类 value syntax 并保留 raw text。Typechecker 负责校验和归一化。

```ts
export interface ChemdReferenceExpr extends ChemdValueBase {
  type: "reference";
  refKind: "local" | "field" | "module" | "external_document";
  target: string;
  moduleName?: string;
  externalDocumentId?: string;
  field?: string;
  resolved?: ReferenceResolution;
}
```

Reference identity 支持 local declarations、field references、
module-qualified declarations、imported aliases，以及
`@external_doc#rxn_step_01` 这样的 external document anchors。

## Documentation Comments

```ts
export interface ChemdDocComment extends SourceMappedNode {
  type: "doc_comment";
  id: string;
  markdown: string;
  attachment:
    | { kind: "file" }
    | { kind: "module"; moduleName: string }
    | { kind: "declaration"; declarationId: string }
    | { kind: "field"; declarationId: string; fieldName: string }
    | { kind: "procedure_step"; declarationId: string; stepId: string }
    | { kind: "agent_statement"; runId: string; statementId: string };
  exportPolicy: "render_rag" | "render_only" | "audit_only";
}
```

Doc references 是 documentation links。Declaration field references 未解析是
error；doc-comment references 未解析是 warning，除非该 doc 是 `audit_only`。

## Procedure and Agent Declarations

`ProcedureDeclaration` 拥有 source-level procedure statements：

```ts
export type ProcedureStatement =
  | { kind: "step"; id: string; family: string; args: Record<string, ChemdValue> }
  | { kind: "control"; controlKind: ProcedureControlKind; children: ProcedureStatement[] }
  | { kind: "doc"; markdown: string };
```

Procedure steps 会 lower 为 canonical step nodes 和 typed step nodes。Procedure
controls 会 lower 为 canonical control nodes 和 runtime control states。Step
parameters 按 step family schema 校验。Control placement 和 condition references
在 typechecking 阶段校验。

`AgentRunDeclaration` 记录 source-level audit intent：goals、tool calls、
evidence、patch proposals、decisions 和 timeline data。Patch targets 必须解析到
program declarations、fields、meta fields 或 doc comments。

## Compiler Integration

Resolver 从 module、imports、meta、declarations 和 docs 构建
`ProgramSymbolTable`。

Typechecker 从 `program.declarations` 校验 declarations、field values、
references、procedures、agents 和 graph-level semantics。

Compiler 和 exporters 必须把 `program.schemaVersion`、`program.sourceLanguage`、
declaration IDs、field source spans 和 doc comment IDs 传递到 typed graph
metadata、diagnostics、semantic diff、training exports、language service navigation
和 storage records。
