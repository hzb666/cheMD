图谱输出来自 training understanding 和 workspace linker 结果。它们描述单文档内部关系、跨 import 文档关系，以及可选 runtime trace input 中的执行关系。

```bash
pnpm chemd graph ./experiments/*.chemd --format json
```

Runtime trace 可以附加到同一个 graph：

```bash
pnpm chemd graph ./experiments/*.chemd --trace trace.json --format json
```

Text 输出会把 graph-index clusters 标成 semantic source truth。只有当输出里已经
包含 merged `reaction_intelligence` layer 时，才显示 computed reaction-intelligence
汇总。

```text
Chemd graph index
  documents: 2
  nodes: 24
  edges: 31
  reactions: 2
  semantic reaction clusters: 1
  semantic reaction similarity edges: 1
  reaction intelligence:
    providers: 3
    strict reaction clusters: 1
    candidate reaction neighbors: 0
    semantic reaction groups: 0
    strict cluster profiles: 1
    warnings: provider_skipped:rxnfp
```

## Knowledge Graph

`training.knowledge_graph` 是单文档图谱。它包含：

- document、molecule、material、reaction、result、analysis、sample、artifact、condition variation、condition attempt、narrative block、procedure、procedure step、observation、observation event、field value 和 normalized value 节点
- 来自 semantic relations、procedure logic、observation logic、field evidence 和 normalization 的边
- `field_evidence`
- `missing_logic`

示例：

```json
{
  "nodes": [
    { "node_id": "reaction::rxn-main", "node_type": "reaction", "original_id": "rxn-main" },
    { "node_id": "result::res-main", "node_type": "result", "original_id": "res-main" },
    { "node_id": "procedure-step::s-add", "node_type": "procedure_step", "label": "add" },
    { "node_id": "observation-event::e-color", "node_type": "observation_event", "label": "color_change" }
  ],
  "edges": [
    {
      "edge_type": "result_describes_reaction",
      "from_node_id": "result::res-main",
      "to_node_id": "reaction::rxn-main",
      "edge_source": "semantic_relation"
    },
    {
      "edge_type": "event_observed_step",
      "from_node_id": "observation-event::e-color",
      "to_node_id": "procedure-step::s-add",
      "edge_source": "observation_logic"
    }
  ],
  "field_evidence": [
    {
      "subject_entity_id": "result::res-main",
      "field": "yield_percent",
      "value": 78,
      "normalized": true,
      "evidence_entity_ids": ["analysis::nmr-main"]
    }
  ],
  "missing_logic": []
}
```

Observation 不是只能作为块级图谱事实。`observation_to_events` 会降低作者写入的 event record，这些 event 节点可以连接 procedure step 或 evidence。Trace record 是 runtime log 与 audit context；它不是主要实验图谱事实。

## Material Flow 与 Step Dependencies

`experiment_logic.material_flow_graph` 包含物料流节点和边。节点覆盖 molecules、reactions、results、analyses、samples、artifacts 和 procedure steps。

`experiment_logic.step_dependencies` 记录 ordered step edges、explicit dependencies、material-flow dependencies、produced artifacts 和 observation-event links。

`experiment_logic.reaction_routes` 记录 route membership、previous reaction IDs、next reaction IDs，以及 reaction 是 root、intermediate、leaf 还是 isolated。

示例：

```json
{
  "material_flow_graph": {
    "nodes": [
      { "node_id": "molecule::mol-a", "node_type": "molecule", "entity_id": "molecule::mol-a" },
```

## Training Graph Index

`chemd graph` 返回 `ChemdTrainingGraphIndexV1`，schema version 为 `chemd-training-graph-index/v0.1`。

它保留已有 training graph 字段：

- `index_scope`
- `nodes`
- `edges`
- `reaction_features`
- `reaction_clusters`
- `reaction_similarity_edges`
- `warnings`

Workspace graph 输出会在同一个 `nodes` 和 `edges` 数组中增加稳定节点与边：

- `document_imports_document`
- `reaction_uses_imported_molecule`
- `reaction_uses_imported_material`
- `reaction_uses_imported_batch`
- `reaction_produces_imported_product`
- `reaction_instantiates_template`
- `reaction_has_previous_reaction`
- `reaction_depends_on_reaction`
- `reaction_precedes_reaction`
- `condition_screen_compares_reaction`
- `condition_screen_uses_standard`
- `procedure_has_control`
- `control_reads_runtime_signal`

Runtime trace input 会增加 execution-order 和 replay-state graph facts：

- `runtime_trace_event` nodes
- `runtime_state_snapshot` nodes
- `trace_event_precedes_event`
- `runtime_state_precedes_state`
- `trace_event_targets_step`
- `trace_event_targets_control`

Trace JSON 使用下面的形状：

```json
{
  "runId": "run-1",
  "stepIds": ["charge", "heat"],
  "events": [
    {
      "eventId": "evt-1",
      "runId": "run-1",
      "timestamp": "2026-06-04T10:00:00.000Z",
      "type": "step_started",
      "stepId": "charge",
      "documentId": "exp-route",
      "procedureId": "proc_main"
    }
  ]
}
```

`documentId` 和 `procedureId` 可选。多个文档存在相同 step 或 control ID 时，它们用于限定 event target。

## Reaction Map

`@chemd/reaction-map` 会把 graph index 转为用于可视化的 `chemd-reaction-cluster-layout/v0.1`。

```ts

const layout = buildReactionMapFromGraphIndex(graphIndex);
```

## Reaction Intelligence

Reaction intelligence 会用计算特征和 similarity edges 增强 graph-index reactions。

provider 运行前，`@chemd/exporter-training` 可以从 graph index 生成 canonical
reaction intelligence input。该输入保留 Chemd 语义上下文，例如 reaction family、
procedure signature、condition signature、route id、changed variables 和
controlled variables。Canonical reaction SMILES 只接受调用方通过显式 chemistry
feature ref 提供的值。没有 canonical reaction SMILES 时，reaction 仍保留在输入里，
并带 `canonical_rxn_smiles_not_available`；Chemd 不会从 prose 或语义分组推断
computed chemistry。

当 canonical input 转成 `chem-cluster-service` job 时，只有 compute-ready reactions
会发送给 providers。缺少 canonical reaction SMILES 的 reactions 会从 provider job
中跳过，并报告
`service_job_reaction_skipped_missing_canonical_rxn_smiles:*`。默认 provider
policy 会禁用网络访问，并把缺失的本地依赖视为 skipped providers。

Hybrid similarity edges 会暴露 contribution-level evidence。Computed chemistry
signals 是主权重：RDKit reaction fingerprint 使用
`rdkit_reaction_directional_8192_v3`，它是由 reactant-side、product-side、
product-gained 和 reactant-lost blocks 构成的 sparse directional vector。每个 side
包含 RDKit path fingerprint `1024` bits 与 Morgan radius-2 fingerprint `1024`
bits；最终 vector 是 `8192` 维。RDKit pair similarity 仍然在每个 block 内使用
Tanimoto，然后按 `0.20` reactant、`0.20` product、`0.30` gained、`0.30` lost
合成。RDKit contribution 在 hybrid 中基础权重为 `0.30`，RXNFP cosine 为
`0.25`，reaction center support 为 `0.25`，Chemd semantic context 为 `0.20`。
当 RDKit 可用时，缺失 component 的权重会全部回补给 RDKit，而不是丢弃。比如
RXNFP 和 reaction-center evidence 缺失时，RDKit 使用 `0.80`，semantic context
保留 `0.20`。如果 RDKit 不可用，才对剩余可用权重重新归一化，且不会伪造 RDKit
evidence。reaction center 冲突且 RDKit support 低时会报告
`strict_cluster_hard_reject:reaction_center_conflict_low_rdkit`；后续 cluster builder
不能把这类 edge 提升为 strict reaction cluster。

service 会按证据强度拆开聚类输出：

- `strict_reaction_clusters` 只来自强 computed / hybrid edges，并排除
  reaction-center hard reject。
- `candidate_reaction_neighbors` 保留较弱 computed neighbors，用于审查或
  UI 提示。
- `semantic_reaction_groups` 只保留 Chemd semantic-only similarity；它们不等同于
  严格化学反应簇。

`strict_reaction_cluster_profiles` 会在 merge 后由 strict clusters 和已有 graph-index
reaction features 生成。它面向 LLM 和训练导出解释 cluster，包括 representative
reaction、共同 family / procedure、score summary、evidence basis、document ids 和
warnings。profile 不会改变 cluster membership。

回归 gold cases 覆盖 strict computed clusters、semantic-only groups、
reaction-center hard rejects 和 skipped provider warnings。

输出包括：

- `ReactionIntelligenceJob`
- `ReactionIntelligenceArtifact`
- `ChemdReactionIntelligenceGraphIndex`

Provider 可以包括 semantic similarity、DRFP、RDKit fingerprints、RXNMapper、RXNFP、reaction center detection 和 TMAP layout。
