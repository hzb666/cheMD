title: Syntax Aliases
description: Chemd field aliases, inline aliases, and accepted shorthand fields.
---

This page lists aliases and shorthand fields accepted by the current Chemd parser and resolver. Prefer the canonical field when writing new documents unless the shorthand is already part of a compact pattern.

## Reaction Fields

| Alias or shorthand | Canonical field | Applies to | Notes |
| --- | --- | --- | --- |
| `reactants` | `reactants` | `:::chemd` reaction | Canonical reactant list. |
| `reactant` | `reactants` | `:::chemd` reaction | Singular shorthand for the reactant list. |
| `reac` | `reactants` | `:::chemd` reaction | Compact shorthand. It has read priority over `reactant` and `reactants`. |
| `products` | `products` | `:::chemd` reaction | Canonical product list. |
| `product` | `products` | `:::chemd` reaction | Singular shorthand for the product list. |
| `prod` | `products` | `:::chemd` reaction | Compact shorthand. It has read priority over `product` and `products`. |

```md
:::chemd #rxn-main
kind: reaction
reac: @mol-a | @mol-b
prod: @mol-c
:::
```

## Primary Inline Aliases

Primary inline aliases resolve through frontmatter `primary_*` fields. They are only valid when followed by a field name.

| Inline alias | Frontmatter source | Example |
| --- | --- | --- |
| `@reaction.field` | `primary_reaction` | `@reaction.solvent` |
| `@result.field` | `primary_result` | `@result.yield` |
| `@product.field` | `primary_product` | `@product.name` |
| `@sample.field` | `primary_sample` | `@sample.purity` |
| `@molecule.field` | `primary_molecule` | `@molecule.smiles` |
| `@analysis.field` | `primary_analysis` | `@analysis.data` |

```md
---
primary_reaction: rxn-main
primary_result: res-main
---

The primary reaction used @reaction.solvent and gave @result.yield.
```

## Result and Condition-Screen Aliases

| Alias or shorthand | Canonical meaning | Applies to | Notes |
| --- | --- | --- | --- |
| `ref` | reaction association | `:::result` | Treated as the reaction link when `reaction` is absent. |
| `reaction` | reaction association | `:::result` | Explicit reaction link; preferred when the relationship should be clear. |
| `note` / `notes` | attempt note | `:::condition-varies` attempt section | Both forms populate the current attempt note. |
| first segment after `attempt:` | attempt ID | `:::condition-varies` | `attempt: mecn-40` opens attempt `mecn-40`. |

```md
:::condition-varies #screen-main
standard: rxn-standard
factor: solvent | baseline=MeCN
factor: temperature | baseline=40 C
outcome: yield | baseline=68 %

attempt: dmf-60
reaction: rxn-var1
result: res-var1
solvent: DMF
temperature: 60 C
yield: 72 %
note: cleaner profile
:::
```

## Procedure and Observation Aliases

| Alias | Canonical field | Applies to | Notes |
| --- | --- | --- | --- |
| `step_id` | `id` | `step:` and nested `:::step` | Sets the authored step ID. |
| `depends_on` | `dependsOn` | `step:` and nested `:::step` | Accepts comma-separated dependency step IDs. |
| `event_id` | `id` | `event:` and nested `:::event` | Sets the authored event ID. |
| `event_type` / `type` | `eventType` | `event:` and nested `:::event` | Sets the event type. |
| `linked_step` | `linkedStep` | `event:` and nested `:::event` | Links the event to a step ID. |

```md
:::procedure #proc-main
step: add | step_id=s-add | inputs=@mol-a | outputs=@mol-b
step: analyze | id=s-tlc | depends_on=s-add
:::

:::observation #obs-main
event: color-change | event_id=e-color | linked_step=s-add
event: event_type=tlc-check | id=e-tlc | linkedStep=s-tlc
:::
```

## Template Binding Aliases

Template `bind` entries are user-defined aliases. They can point to object IDs or primary frontmatter fields, and `:::use` can override a bound alias by passing a field with the same name.

```md
:::template reaction-summary
bind: rxn=primary_reaction | res=primary_result
Reaction @rxn.name gave @res.yield.
:::

:::use reaction-summary
rxn: rxn-variant
res: res-variant
:::
```
