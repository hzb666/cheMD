title: Feature Inventory
description: Field-level inventory of Chemd language, validation, CLI, and export features.
---

This inventory summarizes the language features available to Chemd users. Use it as a checklist when authoring records, validating files, or choosing an export format.

## Language Input Surface

Chemd accepts Markdown prose, YAML frontmatter, `:::` structured blocks, template blocks, column layout blocks, inline references, inline chemistry expressions, inline code, and Markdown links. Supported structured block names include `chemd`, `material`, `batch`, `result`, `analysis`, `artifact`, `sample`, `condition-varies`, `procedure`, `observation`, `use`, and `col`. `template` uses the header fields `bind`, `params`, `description`, and `body`.

Unknown structured blocks produce `W_UNKNOWN_BLOCK`.

## Frontmatter Features

- Required fields: `id`, `title`, and `date`.
- Primary fields: `primary_reaction`, `primary_result`, `primary_product`, `primary_sample`, `primary_molecule`, and `primary_analysis`.
- Tags: `tags` accepts a string array.
- Render selection: `render_profile` accepts a non-empty string, and `render_overrides` accepts a single-level path/value mapping.
- Extra metadata: scalar values are retained in `ChemdMeta`.
- Unsupported value shapes: block scalar, implicit multiline scalar, nested structures outside `tags` or `render_overrides`, and top-level values outside mappings.

`render_overrides` supports these paths: `structure.bondLength`, `structure.bondLineWidth`, `structure.multipleBondOffset`, `structure.hashSpacing`, `structure.fontSize`, `structure.atomLabelPadding`, `structure.monochrome`, `structure.backgroundColor`, `reaction.arrowLength`, `reaction.componentGap`, `reaction.plusGap`, `reaction.showConditionsBelowArrow`, `export.imageFormat`, `export.margin`, `export.dpi`, and `export.transparentBackground`.

## Inline Syntax Features

- `@id`: object reference.
- `@id.field`: object field reference.
- `@reaction.field`, `@result.field`, `@product.field`, `@sample.field`, `@molecule.field`, `@analysis.field`: primary alias field reference.
- `@meta.field`: frontmatter metadata reference.
- `@param.field`: template parameter field reference.
- `:chem[...]`: inline chemistry expression; empty or multiline content is invalid.
- Markdown links: safe href forms include `#`, `/`, `./`, `../`, scheme-free values, `http`, `https`, and `mailto`. Control characters and unsafe schemes produce `W_UNSAFE_LINK_HREF`.

## Field Parsing Features

Field lines use `key: value`. A key starts with a lowercase letter and continues with lowercase letters, digits, or underscores. List fields use `|` or comma separators. Empty list items produce `E_INVALID_LIST_ITEM`. A single line can contain multiple fields separated by `;;`. Block IDs must match `^[a-zA-Z][a-zA-Z0-9_-]*$`.

Default list fields are `reactants`, `products`, `reactant`, `product`, `reac`, `prod`, `conditions`, and `params`. `chemd` also treats `prev` as a list field. `sample` treats `artifacts` and `chemistry_features` as list fields.

## Structured Object Features

- `:::chemd`: produces molecule or reaction by `kind` or field shape. Missing `kind` is inferred from reaction participant fields or molecule identity fields; unstable inference produces a `W_CHEMD_KIND_AMBIGUOUS` error.
- Molecule fields: `smiles`, `canonical_smiles`, `cas`, `inchi`, `inchikey`, `name`, `role`, `caption`, `formula`, `mw`, and `chemistry_features`.
- Reaction fields: `name`, `reactant`, `product`, `reac`, `prod`, `reactants`, `products`, `conditions`, `route`, `prev`, `reagents`, `catalyst`, `solvent`, `temperature`, `time`, `pressure`, `atmosphere`, `yield`, `conversion`, `selectivity`, `equation`, `rxn_smiles`, `caption`, and `chemistry_features`.
- `:::material` fields: `molecule`, `supplier`, `lot`, `purity`, `density`, `storage`, `notes`, and `chemistry_features`.
- `:::batch` fields: `source`, `molecule`, `state`, `mass`, `purity`, `artifacts`, `notes`, and `chemistry_features`.
- `:::result` fields: `status`, `yield`, `conversion`, `selectivity`, `isolated_mass`, `product_state`, `purity`, `notes`, `ref`, `reaction`, and `product`.
- `:::analysis` fields: `type`, `ref`, `time`, `eluent`, `plate`, `visualization`, `result`, `instrument`, `solvent`, `frequency`, `method`, `data`, `notes`, and `p1` through `pN`.
- `:::sample` fields: `name`, `sample_id`, `batch`, `purity`, `supplier`, `notes`, `ref`, `derived_from`, `aliquot_of`, `batch_of`, `artifacts`, and `chemistry_features`.
- `:::artifact` fields: `kind`, `ref`, `path`, `checksum`, `instrument`, `notes`, and `chemistry_features`.
- `:::condition-varies` fields: `reaction`, `standard`, `condition`, `varies`, `varN`, `resN`, `noteN`, and `notes`.
- `:::procedure` fields: `ref`, `reaction`, and `evidence`, with `step:` lines and nested `:::step` blocks.
- `:::observation` fields: `ref`, with `event:` lines and nested `:::event` blocks.
- `:::col` syntax: column count comes from the header argument, such as `:::col-2` or `:::col 2`; children are written as `col:` lines, and each child can contain Markdown or braced structured content.

## Resolver and Typechecker Features

The resolver builds an object index, checks duplicate IDs, resolves inline references, resolves primary aliases, expands templates, and validates required fields. Required fields are material `molecule`, batch `source`, analysis `type_name` and `data`, sample `name`, and artifact `kind` and `path`. Molecule identity and reaction participant presence are enforced by the typechecker. TLC analysis only requires `type_name`.

The typechecker builds the typed semantic graph, step graph, quantity normalization, typed reference checks, result relationship checks, sample relationship checks, reaction route checks, reaction participant stoichiometry checks, and observation event link checks. Quantity units cover amount, mass, volume, temperature, time, pressure, concentration, equivalent, percent, rate, rpm, and pH. Percent values outside 0 to 100 produce `E402`; unparseable quantities and compact number-unit syntax produce `E403`; non-canonical unit casing produces `W_QUANTITY_UNIT_CASING`.

## Procedure and Observation Features

Explicit step families include `charge`, `add`, `transfer`, `mix`, `cool`, `heat`, `hold`, `purge`, `quench`, `extract`, `wash`, `separate_layers`, `filter`, `dry`, `concentrate`, `purify`, `sample`, `analyze`, `observe`, and `store`. `purge` defaults missing `atmosphere` to `nitrogen`.

Explicit observation event types include `color_change`, `precipitation`, `gas_evolution`, and `phase_change`. Events can target a step through `linkedStep` or `linked_step`. Missing step targets produce `E_OBSERVATION_LINKED_STEP_MISSING`.

## Template Features

`:::template name` supports `params`, `bind`, `description`, and body content. Parameter types support `string`, `ref<kind>`, and `quantity<class>`. Reference kinds support molecule, material, batch, reaction, result, analysis, procedure, observation, sample, artifact, and condition_varies. Quantity classes support amount, mass, volume, temperature, time, pressure, concentration, equivalent, percent, rate, rpm, and pH.

Template expansion has maximum depth 32 and maximum expanded node count 2000. Cycles produce `E_TEMPLATE_CYCLE`, unknown templates produce `E_UNKNOWN_TEMPLATE`, missing arguments produce `E_TEMPLATE_PARAM_MISSING`, and type mismatches produce `E_TEMPLATE_PARAM_TYPE_MISMATCH`.

## Compile and Export Features

`compileChemd` executes parse, resolve, typecheck, render profile resolution, runtime run plan, runtime preflight, LNF, training export, RAG export, training understanding, input assistance, input-assistance diagnostics, diagnosis, HTML, JSON, and DOCX bridge.

CLI commands include `validate`, `export`, `graph`, `diff`, `changed`, `repair`, and `agent-loop`. `export` formats include `json`, `lnf`, `rag`, `training`, and `training-full`. Text output formats for `graph`, `diff`, `changed`, `repair`, and `agent-loop` support `text` and `json`.
