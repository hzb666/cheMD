Parser implementation lives in `packages/parser`. The package entrypoint is `packages/parser/src/index.ts`.

## Secondary Topics

### `parseChemd`

`parseChemd(source)` is the public parsing entrypoint. It calls the frontmatter parser, then the body parser, then creates a `ChemdDocument` through `createDocument`.

```ts
import { parseChemd } from "@chemd/parser";

const document = parseChemd(source);
const reaction = document.children.find((node) => node.type === "reaction");
```

### Field Parsing

Field parsing uses `parseKeyValueLine` and `parseKeyValueLines`. Unknown fields are filtered by `parseAllowedFields` and produce `W_UNKNOWN_FIELD` with error severity.

```md
:::chemd #rxn-main
solvent: MeCN ;; temperature: 60 C
reactant: @mol-a | 1.0 mmol | 1.0 eq | limiting=true
reac: @mol-b | 1.2 eq
product: @mol-c
:::
```

The parser splits `;;` into separate field segments and splits configured list fields such as `reactants` with `|`. Structured participant fields use single-field lines (`reactant`, `product`, `reac`, `prod`) so amount, equivalent, mass, volume, and `limiting=true` remain attached to the intended participant. Plural aliases (`reactants`, `products`) are simple list aliases only.

At this layer, field values are still source-preserving strings or string
arrays. `@chemd/core` block schema defines field names, aliases, list modes,
and additive `FieldValueSchema` metadata for value kinds such as enum, quantity,
percent, reference, list, record, chemical, and domain values. Parser behavior
does not consume this metadata yet. Quantity, reference, status, analysis type,
atmosphere, and step parameter typing still run later in the resolver,
typechecker, step ontology, and language-service layers. Typed field value
schema work therefore has to remain metadata-backed and drift-tested before it
can replace existing parser or compiler behavior.

### Current Block Grammar Notes

- The `chemd` parser emits molecule or reaction nodes by explicit `kind`, `kind` value aliases (`mol`, `reac`), or stable field-shape inference. Reaction participants are parsed from canonical `reactant` / `product` fields and compact aliases `reac` / `prod`.
- The `analysis` parser handles typed TLC, NMR, chromatography, and MS records. TLC lines are stateful: `lane:` opens the current lane, then `spot`, `mess`, `base`, and `none` lines attach to that lane. NMR uses `spectrum:` metadata lines plus compact `peak:` lines.
- The `condition-varies` parser accepts only declared `factor`, declared `outcome`, and `attempt` sections. Declaration lines must appear before the first attempt.
- The `procedure` parser accepts `step:` lines, nested `:::step` blocks, and procedure-local control flow: `repeat`, `until`, `branch`, `parallel`, `case`, `default`, `path`, `wait`, and `abort_if`. Brace-delimited controls are parsed inside `:::procedure`; they are not top-level Chemd blocks.
- The `trace` parser records authored runtime `event:` lines under a trace object and is paired with runtime-trace replay code later in the pipeline.

## Implementation Detail Inventory

`parseChildren` is the main body parsing loop. It buffers consecutive ordinary lines into Markdown nodes, flushes the Markdown buffer when it sees a `:::` block start, then dispatches structured blocks. `template` is handled directly by `parseChildren`; other blocks go through `parseStructuredBlock` and then the block parser registry.

`parse-body-shared.ts` contains common syntax handling: block type matching, block line collection, field line parsing, list value parsing, `;;` multi-field splitting, `col:` child support, and Markdown node creation. Field keys start with a lowercase letter. Empty list items produce `E_INVALID_LIST_ITEM`. Keys outside the allowed field set produce error-severity `W_UNKNOWN_FIELD`.

`parse-structured-block.ts` produces error-severity `W_UNKNOWN_BLOCK` for unknown blocks.

Inline tokenizers currently cover references, inline chemistry, inline code, and Markdown links. The reference tokenizer recognizes `@id` and `@id.field`; the inline chemistry tokenizer recognizes `:chem[...]`; the link tokenizer validates href safety and emits `W_UNSAFE_LINK_HREF` for unsafe href values.
