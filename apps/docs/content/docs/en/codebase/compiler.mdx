Compiler implementation lives in `packages/compiler`. Entrypoints include `packages/compiler/src/index.ts` and Node-specific entrypoint `packages/compiler/src/node.ts`.

## Secondary Topics

### Dependency Composition

`@chemd/compiler` depends on parser, resolver, typechecker, render-profile, renderer-html, renderer-json, renderer-docx, exporter-training, runtime-lab, step-ontology, and lnf.

### Compile Entrypoint

`packages/compiler/src/index.ts` is the public compile entrypoint. It aggregates parsing, resolution, type checking, rendering, and export capabilities.

```ts
import { compileChemd } from "@chemd/compiler";

const result = compileChemd(source);

if (result.diagnostics.some((diagnostic) => diagnostic.severity === "error")) {
  throw new Error("Chemd source did not compile cleanly");
}
```

### Node Entrypoint

`packages/compiler/src/node.ts` is exposed through package exports as `@chemd/compiler/node`.

## Compile Pipeline Order

`compileChemd` executes a fixed sequence: `parseChemd`, `resolveChemd`, `typecheckDocument`, render profile resolution, runtime run plan, runtime preflight, canonical LNF, training export, RAG export, training understanding, input assistance, input-assistance diagnostics, compiler diagnosis, HTML, JSON, and DOCX bridge.

`CompileResult` exposes document, diagnostics, renderOptions, renderAdapterPayload, typedSemanticGraph, stepGraph, runPlan, runtimePreflight, lnf, ragExport, trainingUnderstanding, trainingExport, authoringAssistance, diagnosis, html, json, and docxBridge.

## Diagnostics and Safe-Fix Entrypoints

`buildCompilerDiagnosis` partitions diagnostics into safe fixes, required inputs, and manual review items, then provides next actions. `applyCompilerDiagnosisSafeFixes` applies safe fixes in order. The public CLI surface is `chemd fix`; internally, the safe-fix implementation repeats local compilation and safe-fix application before `runChemdAgentLoop` calls an external agent driver.

```bash
pnpm chemd fix draft.chemd --format json
pnpm chemd fix draft.chemd --write
```

## Export Entrypoints

HTML comes from `@chemd/renderer-html`. JSON comes from `@chemd/renderer-json` and includes the typed graph. DOCX bridge comes from `@chemd/renderer-docx` and receives the render adapter payload. Training, RAG, and graph index exports come from `@chemd/exporter-training`.

## Current Language Semantics

Compiler-facing tests and fixtures should cover these language surfaces together:

- `:::chemd` kind inference, `mol` / `reac` aliases, structured `reactant` / `product` participants, and optional `rxn_smiles` inference from participant molecules.
- `:::material` and `:::batch` objects as physical inventory/batch layers referenced by reaction participants.
- `:::analysis` TLC lane/spot shorthand, label-only spot references, NMR `spectrum` / `peak` lines, MS `peak` / `ion` lines, and artifact references.
- `:::condition-varies` factor/outcome/attempt sections with declared baselines and per-attempt outcome values.
- `:::procedure` explicit steps plus control-flow lines and brace blocks: `repeat`, `until`, `branch`, `parallel`, `case`, `default`, `path`, `wait`, and `abort_if`.
- `:::trace` authored runtime events and governance diagnostics that block sanitized non-audit training projections when required.

When a compiler result changes, inspect both user-facing exports and developer-facing semantic structures: diagnostics, typed semantic graph, step graph, run plan, LNF, RAG export, training understanding, and language-service consumers.
