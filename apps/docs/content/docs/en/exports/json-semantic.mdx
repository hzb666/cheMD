---
title: JSON and Semantic Export
description: JSON document output, typed semantic graph, and how it differs from training semantic_layer.
---

JSON export is the structured document export exposed by the CLI:

```bash
pnpm chemd export ./examples/example.chemd --format json
```

It is generated by `@chemd/renderer-json` from the resolved document and typed graph.

## Output Shape

The JSON payload contains:

- `document.meta`: program metadata
- `document.layout`: present when `col` nodes were flattened
- `document.body`: serialized Markdown and structured blocks
- `semantic.typedGraph`: typed semantic graph from the typechecker
- `diagnostics`: compiler diagnostics attached to the document

Arrays are objectified with stable numbered keys such as `01_reaction`, `02_result`, and `01_reactant`. This keeps exported JSON diff-friendly and avoids ambiguous anonymous array entries.

## Example

```json
{
  "document": {
    "meta": {
      "id": "exp-export-example",
      "title": "Export example",
      "date": "2026-05-21",
      "primary_reaction": "rxn-main",
      "primary_result": "res-main"
    },
    "body": {
      "01_molecule": {
        "id": "mol-a",
        "name": "substrate A",
        "smiles": "CCO",
        "source_block_type": "chemd",
        "syntax_origin": "chemd",
        "declared_kind": "mol"
      },
      "02_molecule": {
        "id": "mol-b",
        "name": "product B",
        "smiles": "CC=O",
        "source_block_type": "chemd"
      },
      "03_reaction": {
        "id": "rxn-main",
        "reactants": {
          "01_reactant": "@mol-a | 1.0 mmol | 1.0 eq | limiting=true"
        },
        "products": {
          "01_product": "@mol-b"
        },
        "solvent": "MeCN",
        "temperature": "60 C",
        "source_block_type": "chemd"
      }
    }
  },
  "semantic": {
    "typedGraph": {
      "documentId": "exp-export-example",
      "nodes": {
        "rxn-main": {
          "kind": "reaction",
          "normalizedConditions": {
            "solvent": { "raw": "MeCN", "normalized": "MeCN" },
            "temperature": { "raw": "60 C", "value": 60, "unit": "C" }
          }
        }
      }
    }
  },
  "diagnostics": {}
}
```

## Semantic Graph vs Training Semantic Layer

`semantic.typedGraph` is the compiler/typechecker graph used for validation, normalized quantities, reference checks, reaction participants, route checks, and step checks.

Field value schema metadata does not add a separate export object in JSON.
Instead, it keeps the typechecker and editor aligned on existing field classes.
For example, `temperature`, `time`, `pressure`, result metrics, mass fields,
and purity fields still export as the same `QuantityType` records; their
quantity classes now resolve through the shared schema adapter before falling
back to the shared constants.

`training-full.semantic_layer` is a different export layer used for downstream training and graph projections. It copies and enriches selected facts into stable entities such as `reactions`, `results`, `analyses`, `condition_variation_attempts`, and `links`.

Use JSON export when you need a faithful document structure plus typed compiler semantics. Use training exports when you need learning, RAG, or graph-ready projections.
