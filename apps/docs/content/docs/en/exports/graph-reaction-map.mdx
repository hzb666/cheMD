title: Graph and Reaction Map Exports
description: Knowledge graph, material flow, graph index, reaction map, and reaction intelligence outputs.
---

Graph outputs are built from training understandings. They describe relationships inside one document and across multiple documents.

```bash
pnpm chemd graph ./experiments/*.chemd --format json
```

Text output labels graph-index clusters as semantic source truth. Computed
reaction-intelligence summaries appear only when a merged
`reaction_intelligence` layer is present.

```text
Chemd graph index
  documents: 2
  nodes: 24
  edges: 31
  reactions: 2
  semantic reaction clusters: 1
  semantic reaction similarity edges: 1
  reaction intelligence:
    providers: 3
    strict reaction clusters: 1
    candidate reaction neighbors: 0
    semantic reaction groups: 0
    strict cluster profiles: 1
    warnings: provider_skipped:rxnfp
```

## Knowledge Graph

`training.knowledge_graph` is per document. It contains:

- nodes for document, molecule, material, reaction, result, analysis, sample, artifact, condition variation, condition attempt, narrative block, procedure, procedure step, observation, observation event, field value, and normalized value
- edges from semantic relations, procedure logic, observation logic, field evidence, and normalization
- `field_evidence`
- `missing_logic`

Example:

```json
{
  "nodes": [
    { "node_id": "reaction::rxn-main", "node_type": "reaction", "original_id": "rxn-main" },
    { "node_id": "result::res-main", "node_type": "result", "original_id": "res-main" },
    { "node_id": "procedure-step::s-add", "node_type": "procedure_step", "label": "add" },
    { "node_id": "observation-event::e-color", "node_type": "observation_event", "label": "color_change" }
  ],
  "edges": [
    {
      "edge_type": "result_describes_reaction",
      "from_node_id": "result::res-main",
      "to_node_id": "reaction::rxn-main",
      "edge_source": "semantic_relation"
    },
    {
      "edge_type": "event_observed_step",
      "from_node_id": "observation-event::e-color",
      "to_node_id": "procedure-step::s-add",
      "edge_source": "observation_logic"
    }
  ],
  "field_evidence": [
    {
      "subject_entity_id": "result::res-main",
      "field": "yield_percent",
      "value": 78,
      "normalized": true,
      "evidence_entity_ids": ["analysis::nmr-main"]
    }
  ],
  "missing_logic": []
}
```

Observation is not only a block-level graph fact. `observation_to_events` lowers authored event records, and those event nodes can link to procedure steps or evidence. Trace records are runtime logs and audit context; they are not primary experiment graph facts.

## Material Flow and Step Dependencies

`experiment_logic.material_flow_graph` contains material-flow nodes and edges. Nodes cover molecules, reactions, results, analyses, samples, artifacts, and procedure steps.

`experiment_logic.step_dependencies` records ordered step edges, explicit dependencies, material-flow dependencies, produced artifacts, and observation-event links.

`experiment_logic.reaction_routes` records route membership, previous reaction IDs, next reaction IDs, and whether a reaction is root, intermediate, leaf, or isolated.

Example:

```json
{
  "material_flow_graph": {
    "nodes": [
      { "node_id": "molecule::mol-a", "node_type": "molecule", "entity_id": "molecule::mol-a" },
      { "node_id": "reaction::rxn-main", "node_type": "reaction", "entity_id": "reaction::rxn-main" },
      { "node_id": "procedure-step::s-add", "node_type": "procedure_step", "step_id": "s-add" }
    ],
    "edges": [
      {
        "edge_type": "material_input_to_reaction",
        "from_node_id": "molecule::mol-a",
        "to_node_id": "reaction::rxn-main",
        "logic_source": "explicit",
        "confidence": "high"
      },
      {
        "edge_type": "step_consumes_material",
        "from_node_id": "molecule::mol-a",
        "to_node_id": "procedure-step::s-add",
        "logic_source": "explicit",
        "confidence": "high"
```

## Training Graph Index

`chemd graph` returns `ChemdTrainingGraphIndexV1` with schema version `chemd-training-graph-index/v0.1`.

It contains:

- `index_scope`
- `nodes`
- `edges`
- `reaction_features`
- `reaction_clusters`
- `reaction_similarity_edges`
- `warnings`

## Reaction Map

`@chemd/reaction-map` turns the graph index into `chemd-reaction-cluster-layout/v0.1` for visualization.

```ts
import { buildReactionMapFromGraphIndex } from "@chemd/reaction-map";

const layout = buildReactionMapFromGraphIndex(graphIndex);
```

Example:

```json
{
  "schema_version": "chemd-reaction-cluster-layout/v0.1",
```

## Reaction Intelligence

Reaction intelligence enriches graph-index reactions with computed features and similarity edges.

Before providers run, `@chemd/exporter-training` can derive a canonical reaction
intelligence input from the graph index. This input preserves Chemd semantic
context such as reaction family, procedure signature, condition signature,
route id, changed variables, and controlled variables. Canonical reaction
SMILES are accepted only from explicit chemistry feature references supplied by
the caller. If no canonical reaction SMILES are available, the reaction remains
in the input with `canonical_rxn_smiles_not_available`; Chemd does not infer
computed chemistry from prose or semantic grouping.

When this canonical input is converted into a `chem-cluster-service` job, only
compute-ready reactions are sent to providers. Reactions missing canonical
reaction SMILES are skipped from the provider job and reported with
`service_job_reaction_skipped_missing_canonical_rxn_smiles:*`. The default
provider policy keeps network access disabled and treats missing local
dependencies as skipped providers.

Hybrid similarity edges expose contribution-level evidence. Computed chemistry
signals carry the main weight: RDKit reaction fingerprints use
`rdkit_reaction_directional_8192_v3`, a sparse directional vector built from
reactant-side, product-side, product-gained, and reactant-lost blocks. Each side
contains RDKit path fingerprint `1024` bits plus Morgan radius-2 fingerprint
`1024` bits; the final vector has `8192` dimensions. RDKit pair similarity still
uses Tanimoto inside each block, then combines the blocks as `0.20` reactant,
`0.20` product, `0.30` gained, and `0.30` lost. The RDKit contribution uses
hybrid weight `0.30`, RXNFP cosine uses `0.25`, reaction center support uses
`0.25`, and Chemd semantic context uses `0.20`. Missing provider components are
ignored and the available weights are renormalized. A reaction center conflict
with low RDKit support is reported as
`strict_cluster_hard_reject:reaction_center_conflict_low_rdkit`; later cluster
builders must not promote that edge into a strict reaction cluster.

The service keeps clustering outputs separated by evidence strength:

- `strict_reaction_clusters` are built only from strong computed/hybrid edges
  and exclude hard-rejected reaction-center conflicts.
- `candidate_reaction_neighbors` keep weaker computed neighbors for review or
  UI hints.
- `semantic_reaction_groups` keep Chemd semantic-only similarity separate; they
  are not treated as strict chemical reaction clusters.

`strict_reaction_cluster_profiles` are generated after merge from strict
clusters plus existing graph-index reaction features. They explain the cluster
for LLM and training use with representative reaction, common family/procedure,
score summary, evidence basis, document ids, and warnings. Profiles never
change cluster membership.

Regression gold cases cover strict computed clusters, semantic-only groups,
reaction-center hard rejects, and skipped provider warnings.

Outputs include:

- `ReactionIntelligenceJob`
- `ReactionIntelligenceArtifact`
- `ChemdReactionIntelligenceGraphIndex`

Providers can include semantic similarity, DRFP, RDKit fingerprints, RXNMapper, RXNFP, reaction center detection, and TMAP layout.
