title: Document Model and Frontmatter
description: Chemd source roots, frontmatter fields, date validation, render selection, and block ID rules.
---

A Chemd source file contains frontmatter, Markdown prose, and structured blocks. The parser reads frontmatter first, parses the body next, and produces a `ChemdDocument`.

## Document Root

The current AST root contains these fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `type` | `"document"` | Fixed root marker |
| `meta` | `ChemdMeta` | Parsed frontmatter |
| `children` | `ChemdNode[]` | Markdown nodes and structured nodes |
| `diagnostics` | `Diagnostic[]` | Issues produced by parsing and resolution |
| `source` | `string` | Original source, optional |
| `renderSelection` | `RenderSelection` | Render profile and overrides, optional |

Parsing starts with frontmatter, producing document metadata, the remaining body text, diagnostics, and optional render selection. The body then becomes ordered child nodes.

## Required Frontmatter

`id`, `title`, and `date` are required keys. When a key is missing, the parser keeps a default value and records a diagnostic.

```yaml
---
id: exp-suzuki-screen-001
title: Suzuki coupling solvent screen
date: 2026-04-24
---
```

Use `YYYY-MM-DD` for `date`. The parser checks both the format and the actual calendar value.

## Common Extension Fields

Frontmatter accepts scalar extension fields. The resolver gives semantic meaning to `primary_*` fields.

| Field | Meaning |
| --- | --- |
| `primary_reaction` | Primary reaction object ID |
| `primary_result` | Primary result object ID |
| `primary_product` | Primary product or molecule object ID |
| `primary_sample` | Primary sample object ID |
| `primary_molecule` | Primary molecule object ID |
| `primary_analysis` | Primary analysis object ID |
| `tags` | String array |
| `render_profile` | Render profile ID |
| `render_overrides` | One-level render override object |

```yaml
---
id: exp-total-synthesis-step-07
title: Total synthesis step 07
date: 2026-04-24
primary_reaction: rxn-step-07
primary_result: res-step-07
tags:
  - total-synthesis
  - route-taxol-a
render_profile: publication-acs
render_overrides:
  structure.bondLineWidth: 2.1
---
```

## Block IDs

Structured block IDs are placed in the block header and start with `#`.

```md
:::result #res-main
status: success
yield: 76 %
:::
```

IDs must match `[a-zA-Z][a-zA-Z0-9_-]*`. The parser enforces this rule in `readStructuredBlockId` and emits `E_INVALID_ID` for invalid IDs.

## Field Lines and Lists

Block fields use `key: value`. Field names start with a lowercase letter and may continue with lowercase letters, digits, and underscores.

```md
reactant: @mol-aryl | 1.0 mmol | 1.0 eq | limiting=true
reac: @mol-boron | 1.2 eq
product: @mol-product
conditions: Cu catalyst | air | 80 C | 4 h
```

List fields use `|` as the separator. Current list fields include `reactants`, `products`, `reactant`, `product`, `reac`, `prod`, `conditions`, `params`, and `prev` inside `:::chemd`. For reaction participants, prefer the singular structured fields `reactant` / `product` or compact aliases `reac` / `prod`; plural aliases are simple lists and should not carry amount, equivalent, mass, volume, or `limiting=true`.

Multiple field segments can share one physical line with `;;`. This form is useful for compact notes. Longer experiment records are clearer with one field per line.

```md
solvent: MeCN ;; temperature: 40 C ;; time: 2 h
```
