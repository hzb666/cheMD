---
title: '`:::col` Column Layout Block'
description: '`:::col` is a presentation-layer layout block for placing Markdown or structured content into columns.'
---

`:::col` is parsed by the block parser registry. It affects rendering layout and does not change chemical semantics.

## Syntax

```md
:::col-2
col: { Reaction summary }
col: { Result summary }
:::
```

`:::col-2` is parsed as `blockType=col` with `columns=2`. `:::col 2` is also valid.

## Children

Each child must start with `col:`. Children support three forms:

| form | notes |
| --- | --- |
| `col: text` | inline Markdown |
| `col: { text }` | single-line wrapped content |
| `col: {` | multiline wrapped content |

```md
:::col-2
col: {
:::result #res-main
status: success
yield: 82 %
:::
}
col: The product was confirmed by NMR.
:::
```

## Defaults and Diagnostics

Column count must be an integer greater than or equal to 1. Invalid counts produce `W_INVALID_COL_COLUMNS` and fall back to 1. A mismatch between declared count and `col:` children produces `W_COL_COUNT_MISMATCH`. Non-`col:` child lines produce `W_INVALID_COL_CHILD`. Unterminated braced content produces `W_UNTERMINATED_BRACE_BLOCK`.

## Recommended Practice

Use `col` for side-by-side summaries. Key semantic objects should still be declared as normal structured blocks.

```md
:::col-2
col: Reaction @rxn-main.name reached @res-main.yield isolated yield.
col: Analysis @ana-tlc-main.data supported completion.
:::
```
