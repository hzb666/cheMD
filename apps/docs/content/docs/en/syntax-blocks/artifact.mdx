---
title: '`:::artifact` Artifact Block'
description: '`:::artifact` records spectra, images, raw data files, and other evidence attachments.'
---

`:::artifact` links file evidence to reactions, results, analyses, or samples.

## Syntax

```md
:::artifact #art-nmr-product
kind: nmr_spectrum
ref: @sample-product
path: data/nmr/product-1h.pdf
checksum: sha256:abc123
instrument: Bruker 400
notes: 1H NMR spectrum for purified product
:::
```

## Fields

| field | required | notes |
| --- | --- | --- |
| `kind` | yes | artifact type |
| `ref` | no | supported object reference |
| `path` | yes | file path |
| `checksum` | no | checksum |
| `instrument` | no | acquisition instrument |
| `notes` | no | notes |
| `chemistry_features` | no | feature ID list |

## Required Fields and Defaults

The resolver requires `kind` and `path`. The parser sets no defaults.

## Recommended Practice

Artifacts should use stable IDs. `kind` should describe the file role, and `ref` should point to the most direct evidence target.

```md
:::artifact #art-hplc-product
kind: hplc_chromatogram
ref: @res-main
path: data/hplc/product-purity.pdf
checksum: sha256:9d5e
instrument: Agilent 1260
notes: purity trace for isolated product
:::
```

## Diagnostics

| code | condition |
| --- | --- |
| `E_INVALID_ID` | invalid artifact ID |
| `W_UNKNOWN_FIELD` | undeclared field |
| `E_MISSING_REQUIRED_FIELD` | missing `kind` or `path` |
| `E_TYPED_REFERENCE_MISMATCH` | `ref` target kind violates relationship rules |
