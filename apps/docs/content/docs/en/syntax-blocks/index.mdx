## Block Inventory

| block | purpose | primary node |
| --- | --- | --- |
| `:::chemd` | molecule and reaction objects | `molecule` or `reaction` |
| `:::material` | inventory material or reagent lot | `material` |
| `:::batch` | generated or purified physical batch | `batch` |
| `:::result` | experimental outcome | `result` |
| `:::analysis` | analytical record | `analysis` |
| `:::procedure` | experimental procedure | `procedure` |
| `:::step` | nested procedure step | `step` |
| `:::observation` | observation record | `observation` |
| `:::trace` | runtime trace record | `trace` |
| `:::event` | nested observation event | `event` |
| `:::sample` | sample record | `sample` |
| `:::artifact` | spectra, images, files, and attachments | `artifact` |
| `:::condition-varies` | condition screening and deltas | `condition_varies` |
| `:::template` | reusable usage template | `template` |
| `:::use` | template invocation | `use` |
| `:::col` | column layout | `col` |

## Block Field Reference

This table lists the parser-accepted fields for each block. `Required` means the resolver or typechecker reports an error when the field or equivalent semantic input is missing.

| block | fields | required | defaults |
| --- | --- | --- | --- |
| `:::chemd` | `kind`, `smiles`, `cas`, `inchi`, `inchikey`, `canonical_smiles`, `name`, `role`, `caption`, `formula`, `mw`, `amount`, `equivalents`, `reactant`, `product`, `conditions`, `route`, `prev`, `equation`, `rxn_smiles`, `reagents`, `catalyst`, `solvent`, `temperature`, `time`, `pressure`, `atmosphere`, `yield`, `conversion`, `selectivity`, `chemistry_features` | reaction nodes require `reactant` and `product`; molecule nodes need at least one identity field for typechecking | `kind` is inferred only when field shape is unambiguous; object ID is generated when omitted |
| `:::material` | `molecule`, `supplier`, `lot`, `purity`, `density`, `storage`, `notes`, `chemistry_features` | `molecule` | object ID is generated when omitted |
| `:::batch` | `source`, `molecule`, `state`, `mass`, `purity`, `notes`, `artifacts`, `chemistry_features` | `source` | object ID is generated when omitted |
| `:::result` | `status`, `yield`, `conversion`, `selectivity`, `isolated_mass`, `product_state`, `purity`, `notes`, `ref`, `reaction`, `product` | none | object ID is generated when omitted |
| `:::analysis` | `type`, `ref`, `time`, `eluent`, `plate`, `visualization`, `result`, `instrument`, `solvent`, `frequency`, `method`, `artifact`, `spectrum`, `lane`, `spot`, `mess`, `base`, `none`, `peak`, `ion`, `data`, `notes`, `pN` | `type` | TLC defaults `plate` to `silica gel GF254` and `visualization` to `UV 254 nm`; object ID is generated when omitted |
| `:::procedure` | `ref`, `reaction`, `evidence`; child lines `step`, `repeat`, `until`, `branch`, `parallel`, `wait`, `abort_if` | none at block level | object ID and anonymous step IDs are generated when omitted |
| `:::step` | `id`, `step_id`, `family`, `inputs`, `outputs`, `depends_on`, `stage`, `purpose`, `evidence`, `confidence`; other fields become params | `family` for nested block form; some families require params | anonymous steps get `<procedure-id>:sN`; `purge` defaults `atmosphere` to `nitrogen` |
| `:::observation` | `ref`; child line `event` | none | object ID is generated when omitted; anonymous events get `<observation-id>:eN` |
| `:::event` | `id`, `event_id`, `type`, `stage`, `timepoint`, `severity`, `linked_step`, `evidence`, `confidence`; other fields become params | `type` for nested block form | event ID is generated when omitted |
| `:::trace` | `plan`, `mode`; child line `event` | `plan` is required by trace typechecking | object ID is generated when omitted |
| `:::sample` | `name`, `sample_id`, `batch`, `purity`, `supplier`, `notes`, `ref`, `derived_from`, `aliquot_of`, `batch_of`, `artifacts`, `chemistry_features` | `name` | object ID is generated when omitted |
| `:::artifact` | `kind`, `ref`, `path`, `checksum`, `instrument`, `notes`, `chemistry_features` | `kind`, `path` | object ID is generated when omitted |
| `:::condition-varies` | `reaction`, `standard`, `factor`, `outcome`, `attempt`, `notes` | none at block level; every `attempt` needs an id | object ID is generated when omitted |
| `:::template` | `params`, `bind`, `description`, `body` | template name in the header | none |
| `:::use` | arbitrary template parameter fields | target template name in the header; required params come from the template | list values are joined with ` | ` |
| `:::col` | `columns`, `col:` child entries | none | invalid column count falls back to `1` |

## Shared Rules

A block starts with `:::block-name`. Object IDs are header arguments written as `#id`. IDs must match `[a-zA-Z][a-zA-Z0-9_-]*`. Fields use `key: value`; keys start with a lowercase letter and then allow lowercase letters, digits, and underscores. A physical line can contain multiple fields separated by `;;`.

```md
:::result #res-main
status: success ;; yield: 82% ;; purity: 96%
:::
```

List handling is block-specific. The default list fields are `reactants`, `products`, `reactant`, `product`, `reac`, `prod`, `conditions`, and `params`. Empty list items produce `E_INVALID_LIST_ITEM`.

## Recommended Organization

A typical experiment record declares molecules first, then reactions, followed by procedure, observation, analysis, result, sample, and artifact blocks. Condition screening records should organize standard and variation reactions around the screening block.

```md validate
---
id: exp-user-guide
title: User guide example
date: 2026-05-19
primary_reaction: rxn-main
primary_result: res-main
---

:::chemd #mol-substrate
name: substrate
smiles: CCO
:::

:::chemd #mol-product
name: product
smiles: CC=O
:::

:::chemd #rxn-main
reactant: @mol-substrate | 1.00 mmol | 1.0 eq | limiting=true
product: @mol-product
solvent: MeCN
temperature: 60 C
time: 3 h
:::

:::result #res-main
reaction: @rxn-main
product: @mol-product
status: success
yield: 74%
:::
```
