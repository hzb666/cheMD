---
title: '`:::event` and `event:` Observation Event Syntax'
description: '`event` is nested observation syntax with type, stage, timepoint, severity, step link, evidence, and confidence.'
---

`event` is valid only inside `:::observation`. The current typechecker supports `color_change`, `precipitation`, `gas_evolution`, and `phase_change`.

## Two Forms

```md
event: color_change | id=e-color | color=yellow | linkedStep=s-heat
```

```md
:::event #e-phase
type: phase_change
stage: extraction
value: clear phase separation
linkedStep: s-extract
:::
```

## Structural Fields

| field | notes |
| --- | --- |
| `id` / `event_id` | event ID; nested blocks can also read it from `#id` |
| `type` / `eventType` / `event_type` | event type |
| `stage` | stage |
| `timepoint` | timepoint |
| `severity` | severity |
| `linked_step` / `linkedStep` | linked step ID |
| `evidence` | evidence IDs separated by `,` |
| `confidence` | numeric confidence |

Other fields become `params`. `value`, `color`, or `state` can become the normalized value candidate.

Nested `:::event` blocks can read the ID from `#id` or from a bare header value. If no ID is supplied, the parser assigns `<observation-id>:eN`.

```md
:::observation #obs-main
:::event e-color
type: color_change
color: orange
:::

:::event
type: gas_evolution
severity: low
:::
:::
```

## Recommended Practice

```md
:::event #e-color
type: color_change
stage: reaction
timepoint: 5 min after addition
severity: medium
color: orange to red
linkedStep: s-add
evidence: photo-color-1
confidence: 0.85
:::
```
