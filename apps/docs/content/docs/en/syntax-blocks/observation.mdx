---
title: '`:::observation` Observation Block'
description: '`:::observation` records observation prose and can contain structured events.'
---

`:::observation` supports free prose, inline `event:` lines, and nested `:::event` blocks.

## Syntax

```md
:::observation #obs-main
ref: @rxn-main
event: color_change | id=e-color | color=deep red | linkedStep=s-add | confidence=0.8
The mixture turned deep red after n-BuLi addition.
:::
```

## Fields

| field | required | default | notes |
| --- | --- | --- | --- |
| `ref` | no | none | observation target reference |
| `event:` child line | no | none | creates a structured event inside this observation |
| nested `:::event` | no | none | creates a structured event block inside this observation |

`observation` has no resolver-required fields. When explicit events are absent, the typechecker passes the prose body to step ontology lowering.

## Structured Events

Events support inline `event:` syntax and nested `:::event` blocks. Explicit events are stored in `events`, while prose remains in `body`.

```md
:::observation #obs-workup
ref: @rxn-main

:::event #e-precipitate
type: precipitation
stage: workup
timepoint: after water addition
value: white solid
linkedStep: s-quench
evidence: photo-workup
confidence: 0.9
:::

A white solid appeared after water addition.
:::
```

The nested event header also accepts a bare ID, such as `:::event e-color`. If the header and fields do not provide an ID, the parser assigns `<observation-id>:eN`.

### Event Fields

| field | required | default | notes |
| --- | --- | --- | --- |
| `id` | no | `<observation-id>:eN` when omitted | event ID; alias: `event_id` |
| `type` | yes | none | event type; aliases: `eventType`, `event_type` |
| `stage` | no | none | experiment stage |
| `timepoint` | no | none | time or relative point in the procedure |
| `severity` | no | none | qualitative severity |
| `linked_step` | no | none | step ID link; alias: `linkedStep` |
| `evidence` | no | none | comma-separated evidence IDs |
| `confidence` | no | none | numeric confidence |
| other fields | no | none | stored as event `params`; `value`, `color`, or `state` can become normalized value candidates |

Inline events use the first segment as the type unless it is written as `type=...`:

```md
event: color_change | id=e-color | color=orange | linkedStep=s-add
event: type=phase_change | id=e-phase | value=clear upper layer
```

## Diagnostics

| code | condition |
| --- | --- |
| `E_INVALID_ID` | invalid observation ID |
| `W_UNKNOWN_FIELD` | top-level field outside `ref` |
| `E_OBSERVATION_EVENT_INVALID_TYPE` | event type is unsupported |
| `E_OBSERVATION_LINKED_STEP_MISSING` | `linkedStep` references a missing step |

## Recommended Practice

Record structured changes as events and keep descriptive detail in prose.

```md
:::observation #obs-main
ref: @rxn-main
event: color_change | id=e-color | stage=reaction | timepoint=after addition | color=orange | linkedStep=s-add | evidence=photo-1
event: gas_evolution | id=e-gas | severity=low | linkedStep=s-quench
Mixture became orange after addition. Mild bubbling occurred during quench.
:::
```
