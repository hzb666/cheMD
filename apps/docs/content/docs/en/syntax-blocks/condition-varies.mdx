---
title: '`:::condition-varies` Condition Screening Block'
description: '`:::condition-varies` declares factors, outcomes, and attempt sections for condition screening.'
---

`:::condition-varies` records a condition screen as declared factors, declared outcomes, and one or more attempt sections. Declarations must appear before the first `attempt:`.

## Syntax

```md
:::condition-varies #cv-screen
standard: @rxn-standard

factor: solvent | baseline=THF
factor: temperature | baseline=25 C
factor: catalyst | baseline=Pd(PPh3)4

outcome: yield | baseline=68%
outcome: conversion | baseline=85%

attempt: var1
result: @res-var1
solvent: MeCN
temperature: 40 C
yield: 72%
conversion: 90%
note: Higher conversion while keeping same catalyst.

attempt: var2
solvent: DMF
temperature: 60 C
catalyst: Pd(dppf)Cl2
yield: 45%
conversion: 70%
:::
```

`attempt:` opens a section. Ordinary fields after it belong to that attempt until the next `attempt:` or the end of the block. Blank lines do not affect ownership.

## Fields

| field | notes |
| --- | --- |
| `standard` | baseline reaction reference |
| `reaction` | optional variation-level reaction link; attempt-level `reaction` is preferred |
| `factor` | varied or controlled input, with optional `baseline=` |
| `outcome` | measured output, with optional baseline |
| `attempt` | attempt id and optional header params |
| `result` | optional result block reference for the current attempt |
| `note` / `notes` | current attempt note |

Factor and outcome names must be declared before use, cannot overlap, and cannot use reserved names such as `reaction`, `standard`, `condition`, `varies`, `factor`, `outcome`, `attempt`, `result`, `note`, or `notes`.

## Semantics

If a factor is omitted inside an attempt, that attempt inherits the factor baseline. If an outcome is declared, every attempt must provide that outcome. Outcome baseline can describe the standard result; when a linked standard/result block provides the same value and conflicts with the explicit baseline, validation reports an error.

`result: @res-id` is optional. If present, it must reference a result block. Attempt outcome values must not conflict with the linked result fields.

## Diagnostics

| code | condition |
| --- | --- |
| `E_CONDITION_DSL_DECLARATION` | duplicate or reserved factor/outcome name |
| `E_CONDITION_DSL_ORDER` | declarations appear after an attempt |
| `E_CONDITION_ATTEMPT_ID` | missing or duplicate attempt id |
| `E_CONDITION_ATTEMPT_UNKNOWN_FIELD` | attempt field was not declared |
| `E_CONDITION_ATTEMPT_DUPLICATE_FIELD` | attempt repeats a factor/outcome |
| `E_CONDITION_OUTCOME_MISSING` | attempt omits a declared outcome |
| `E_CONDITION_BASELINE_CONFLICT` | declared baseline conflicts with inferred standard result |
| `E_CONDITION_OUTCOME_CONFLICT` | attempt outcome conflicts with linked result |
