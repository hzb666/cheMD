## `:::col`

`:::col` produces a `ColNode`. The header argument is the column count. The count must be an integer greater than or equal to 1.

```md
:::col 2
col: {:::result #res-main
status: success
:::
:::}
col: {:::analysis #ana-main
type: tlc
data: TLC evidence
:::
:::}
:::
```

## `col:` Children

`:::col` children must be written as `col:` lines. Inline content creates Markdown child nodes, `col: { ... }` parses wrapped Markdown, and `col: {:::` enters structured-block parsing.

```md
:::col 2
col: left column summary with @reaction.solvent
col: right column summary with @result.yield
:::
```

Structured children are wrapped in braces and closed with `:::}`.

```md
:::col 2
col: {:::result #res-left
status: success
:::
:::}
col: {:::analysis #ana-right
type: tlc
data: product spot observed
:::
:::}
:::
```

Directly nested blocks do not create column children. The parser reports non-`col:` lines as `W_INVALID_COL_CHILD`, and it can also emit `W_COL_COUNT_MISMATCH` when the child count differs from the declared column count.

```md
:::col 2
:::result #res-left
status: success
:::
:::analysis #ana-right
type: tlc
data: product spot observed
:::
:::
```

## Structured Blocks Inside Columns

`ColNode.children` can contain any `ChemdNode`. The resolver recursively handles `col.children` when building object indexes, assigning generated IDs, and resolving nodes.

```md
:::col 3
col: {:::chemd #mol-a
smiles: CCO
:::
:::}
col: {:::result #res-a
status: success
yield: 62 %
:::
:::}
col: {:::artifact #art-a
kind: nmr
path: data/nmr/a.jdx
:::
:::}
:::
```

The molecule, result, and artifact inside the three-column layout are normal objects. `@mol-a`, `@res-a`, and `@art-a` are available outside the layout block.

## Column Count Validation

Invalid column counts produce `W_INVALID_COL_COLUMNS` and fall back to 1. Child-count mismatches produce `W_COL_COUNT_MISMATCH`.

```md
:::col two
col: {:::result #res-invalid-columns
status: success
:::
:::}
:::
```

`two` is not an integer, so the parser emits `W_INVALID_COL_COLUMNS` and falls back to 1.

```md
:::col 2
col: {:::result #res-only-child
status: success
:::
:::}
:::
```

The column count is 2 but there is only one child block, so the parser emits `W_COL_COUNT_MISMATCH`. Object indexing and reference resolution still proceed.

## Language and Renderer Boundary

`col` is a layout node in the AST. HTML, DOCX bridge, and other renderers decide visual presentation. The language layer stores column count and child nodes, with no CSS or page-size data.

```md
:::col 2
col: {:::procedure #proc-left
step: charge substrate and solvent
:::
:::}
col: {:::observation #obs-right
event: color_change from colorless to yellow
:::
:::}
:::
```

The source expresses two columns and two child nodes. Column widths, gaps, breakpoints, and mobile stacking are renderer responsibilities.

## Best Practice Example

Use `:::col` for presentation grouping after semantic objects already have stable IDs. Structured children inside columns still participate in reference resolution.

```md
:::chemd #mol-layout-substrate
smiles: CCO
:::

:::chemd #mol-layout-product
smiles: CC=O
:::

:::chemd #rxn-layout
reactant: @mol-layout-substrate | 1.0 mmol | 1.0 eq | limiting=true
product: @mol-layout-product
:::

:::col 2
col: Reaction @rxn-layout used @mol-layout-substrate.
col: {:::result #res-layout
reaction: @rxn-layout
product: @mol-layout-product
status: success
yield: 72 %
:::
:::}
:::
```
