---
title: Derived Expressions
description: Equal-sign derived quantity expressions, functions, references, units, and diagnostics supported by the Chemd typechecker.
---

Derived expressions apply to quantity fields during validation. An expression must start with `=`, and the computed result is then parsed as the target quantity class.

## Supported Fields

The current implementation evaluates derived expressions through `readQuantity`. These object fields support derived expressions:

| Object | Fields |
| --- | --- |
| reaction | `temperature`, `time`, `pressure` |
| reaction participant | `amount`, `mass`, `volume`, `equiv`, `equivalents` |
| result | `yield`, `conversion`, `selectivity`, `purity`, `isolated_mass` |
| material | `purity` |
| batch | `mass`, `purity` |
| sample | `purity` |

Procedure step parameters are parsed as quantities, but they are not evaluated through derived expressions in the current implementation.

## Literals and Operators

Expressions support numbers, quantity literals, field references, parentheses, unary minus, and arithmetic operators.

```md
:::result #res-derived
reaction: @rxn-main
status: success
isolated_mass: = 120 mg + 30 mg
yield: = percent(0.78, 1)
:::
```

Quantity addition and subtraction require matching units. Multiplying a quantity by a number and dividing a quantity by a number preserve the quantity unit. Division by zero produces an expression error.

## Field References

Field references inside expressions use `@id.field`. The target field must exist and must be a string value. The expression parser interprets referenced values as numbers, quantities, or strings.

```md
:::result #res-calc
reaction: @rxn-main
status: success
isolated_mass: = @res-crude.isolated_mass * 0.72
:::
```

Field references are useful for reusing recorded weights, conversions, or yields. Missing fields, non-string values, and invalid reference syntax produce `E_DERIVED_EXPRESSION_INVALID` for the whole expression.

## Functions

The supported function set is intentionally small and deterministic.

| Function | Semantics |
| --- | --- |
| `sum(a, b, ...)` | Adds all arguments |
| `percent(value, denominator)` | Returns a percent quantity |
| `ratio(value, denominator)` | Returns a numeric ratio |
| `coalesce(a, b, ...)` | Returns the first non-empty string value |
| `to_unit(quantity, unit)` | Converts mass, amount, or volume units |
| `theoretical_yield(a, b, ...)` | Multiplies arguments in sequence |

`to_unit` supports implemented conversions among `mg`, `g`, `kg`; `mmol`, `mol`; and `mL`, `L`. The target unit is written as an identifier, for example `to_unit(1 g, mg)`.

## Diagnostics

Expression parse errors, reference errors, function errors, and invalid arithmetic produce `E_DERIVED_EXPRESSION_INVALID`. After successful evaluation, the result is still parsed by the target quantity class. Quantity-class mismatches can still produce `E403`.

## Best Practice

```md
:::result #res-main
reaction: @rxn-main
product: @mol-product
status: success
isolated_mass: = to_unit(0.126 g, mg)
yield: = percent(0.84, 1)
purity: 98%
:::
```

Derived expressions are suitable for traceable calculations. Keep raw experimental values in separate fields or adjacent records, and use expression fields for standardized derived values.
