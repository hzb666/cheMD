title: Training Graph and Reaction Map
description: How training exports, graph indexes, and reaction maps represent Chemd source records for downstream learning and visualization.

Training and graph outputs are downstream projections. They add no new input syntax. Stable IDs, reaction links, steps, observations, and condition attempts directly affect downstream structural quality.

## Training Export Layers

The training exporter builds `ChemdTrainingExportV2`. The record is organized into four layers:

- `source_layer`: document identity, source spans, and parsed-source context.
- `semantic_layer`: molecules, reactions, results, analyses, samples, artifacts, conditions, procedures, observations, and routes.
- `learning_layer`: retrieval chunks, resolved references, task-oriented projections, and procedure or observation logic.
- `quality_layer`: diagnostics, missing logic, conflicts, confidence, governance quality, and export quality signals.

The top-level `governance` record controls sanitized projections. `training` and `rag` use sanitized data. `training-full` keeps audit-only source context and lists audit-only fields in `source_layer.audit_only_fields`.

```bash
pnpm chemd export ./examples/example.chemd --format training
pnpm chemd export ./examples/example.chemd --format training-full
pnpm chemd export ./examples/example.chemd --format rag
```

Use `training` when a compact training understanding is enough. Use `training-full` when the downstream consumer needs the complete layered record.

## Graph Index

The graph command compiles multiple documents and builds a graph index with schema version `chemd-training-graph-index/v0.1`.

```bash
pnpm chemd graph ./corpus --format json > ./graph-index.json
```

The graph index is built from training understandings after compilation. It is not part of the compiler `CompileResult`.

## Reaction Map

`@chemd/reaction-map` turns graph-index reaction features and similarity edges into a deterministic layout.

```ts
import { buildReactionMapFromGraphIndex } from "@chemd/reaction-map";

const layout = buildReactionMapFromGraphIndex(graphIndex);
```

The layout schema is `chemd-reaction-cluster-layout/v0.1`. It contains:

- `nodes`: reaction nodes with position, quality tier, feature refs, evidence, and warnings.
- `edges`: reaction similarity edges with score, confidence, basis, evidence, and warnings.
- `clusters`: deterministic reaction clusters by reaction signature, procedure signature, condition signature, or reaction family.
- `input_summary`: counts for reactions, edges, clusters, and singletons.

Current layout generation uses a deterministic fallback engine. It keeps output stable for tests and editor previews even when no external embedding or TMAP layout is available.

## Input Guidance

Prefer explicit IDs for reactions, steps, observations, artifacts, and condition attempts. Link results to reactions through `reaction` or a reaction-shaped `ref`, connect observations to steps, and preserve route references. These links become graph evidence instead of disconnected text.

## Best Practice Example

Graph-ready records connect route, result, procedure, observation, sample, and artifact evidence through IDs.

```md
:::chemd #rxn-step-1
route: route-a
reactant: @mol-a | 1.0 mmol | 1.0 eq | limiting=true
product: @mol-b
:::

:::chemd #rxn-step-2
route: route-a
prev: @rxn-step-1
reactant: @mol-b | 1.0 mmol | 1.0 eq | limiting=true
product: @mol-c
:::

:::procedure #proc-step-2
reaction: @rxn-step-2
step: add | id=s-add | inputs=@mol-b | outputs=mixture-step-2
:::

:::observation #obs-step-2
ref: @rxn-step-2
event: color_change | id=e-color | linkedStep=s-add | color=yellow
:::
```
