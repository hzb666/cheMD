---
title: References, Aliases, and Field Access
description: Complete language reference for object references, field references, primary aliases, metadata, template parameters, and condition-screen attempts.
---

Chemd references can appear in Markdown prose, structured fields, template bodies, and layout text. They support object references, field access, primary aliases, metadata access, and template parameter access.

## Object References

Object references use `@id`. The ID must start with a letter and may continue with letters, digits, underscores, and hyphens. The resolver looks up the target in the object index.

```md
The reaction @rxn-main produced @mol-product.
```

Structured fields can also use object references. Use `@id` for relationships that need type checking, especially reaction `reactants`, reaction `products`, result `reaction`, result `product`, and sample `artifacts`.

```md
:::result #res-main
reaction: @rxn-main
product: @mol-product
status: success
yield: 81%
:::
```

## Field References

Field references use `@id.field`. The resolver reads the real AST field from the target object. The field name must start with a letter and may continue with letters, digits, underscores, and hyphens.

```md
The main reaction used @rxn-main.solvent at @rxn-main.temperature.
```

Field references are suitable for narrative text. Missing fields or missing objects produce unresolved reference diagnostics.

## Primary Aliases

`primary_*` frontmatter fields provide aliases for prose. The current implementation supports sources such as `@reaction.field`, `@result.field`, `@product.field`, `@sample.field`, `@molecule.field`, and `@analysis.field`. The target is provided by fields such as `primary_reaction`, `primary_result`, and `primary_product`.

```md
---
id: exp-primary
title: Primary aliases
date: 2026-04-24
primary_reaction: rxn-main
primary_result: res-main
primary_product: mol-product
---

The primary reaction used @reaction.solvent and gave @result.yield of @product.name.
```

Use primary aliases in reader-facing prose. Use explicit `@id` references in structured fields so object relationships remain easy to audit.

## Metadata References

`@meta.field` references frontmatter. This syntax is suitable for document IDs, titles, dates, projects, users, and status values in prose.

```md
Document @meta.id was recorded on @meta.date.
```

`@meta.field` reads metadata from the current document. Complex values are not expanded into nested fields.

## Template Parameter References

Template bodies use `@param.name` to reference values passed by `:::use`. Parameter names come from the template `params` declaration.

```md
:::template result-note
params: sample: ref<sample> | method: string
Sample @param.sample was analyzed by @param.method.
:::

:::use result-note
sample: @sample-main
method: HPLC
:::
```

Template expansion substitutes parameter values into the template body. `ref<kind>` and `quantity<class>` parameters are validated before expansion.

## Condition-Screen Attempt References

Attempts produced by `:::condition-varies` can be referenced with `@screen.var1`. Attempt data comes from `varN`, while result and note data come from `resN` and `noteN`.

```md
:::condition-varies #screen-base
reaction: @rxn-main
condition: solvent=MeCN ;; temperature=60 C
varies: solvent
var1: solvent=DMF
res1: yield=72%
note1: cleaner TLC
:::

The first screen attempt is @screen-base.var1.
```

This reference is useful for screen narratives. To include a screen outcome in the result graph, create a `:::result` block and assign it from the attempt with `result=@res-id`.

## Best Practice

```md
---
id: exp-reference-best-practice
title: Reference best practice
date: 2026-04-24
primary_reaction: rxn-main
primary_result: res-main
primary_product: mol-product
---

The primary reaction used @reaction.solvent at @reaction.temperature.
The isolated product was @product.name with @result.yield yield.

:::result #res-main
reaction: @rxn-main
product: @mol-product
status: success
yield: 84%
:::
```

The prose uses primary aliases for readability. Structured fields use explicit object references for resolver and typechecker relationships.
