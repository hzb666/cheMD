---
title: References, Primary Aliases, and Inline Syntax
description: Chemd @ references, primary aliases, metadata references, template parameter references, and inline chemistry tokens.
---

Chemd preserves Markdown prose and extracts reference, inline chemistry, inline code, and Markdown link tokens. Reference resolution runs after AST construction.

## Object References

Object references use `@id`.

```md
The selected entry is @rxn-var1.
```

The resolver looks up `rxn-var1` in the object index. The object index includes ID-bearing molecule, material, batch, reaction, result, analysis, procedure, trace, observation, sample, artifact, and condition-varies nodes.

## Object Field References

Field references use `@id.field`.

```md
The isolated yield is @res-var1.yield.
```

The resolver finds the object first and then reads the field. Missing fields produce `W_UNRESOLVED_REFERENCE`.

## Primary Aliases

These aliases are bound by frontmatter `primary_*` fields:

| Reference | Frontmatter field |
| --- | --- |
| `@reaction.field` | `primary_reaction` |
| `@result.field` | `primary_result` |
| `@product.field` | `primary_product` |
| `@sample.field` | `primary_sample` |
| `@molecule.field` | `primary_molecule` |
| `@analysis.field` | `primary_analysis` |

```yaml
---
id: exp-condition-screen
title: Suzuki coupling condition screen
date: 2026-04-24
primary_reaction: rxn-var1
primary_result: res-var1
---
```

```md
The selected reaction uses @reaction.solvent and gives @result.yield.
```

Primary aliases are classified as `alias_field` only when a field is present. `@reaction` alone is treated as a regular object ID lookup.

## Metadata References

Metadata references use `@meta.field`.

```md
Experiment @meta.id was recorded on @meta.date.
```

The resolver reads the value from `document.meta`. Missing metadata fields produce unresolved-reference diagnostics.

## condition-varies Attempt References

A `condition_varies` node exposes attempts through field lookup.

```md
:::condition-varies #cv-screen
standard: @rxn-standard
factor: solvent | baseline=THF
factor: temperature | baseline=25 C
outcome: yield | baseline=68 %

attempt: var1
reaction: @rxn-var1
result: @res-var1
solvent: MeCN
temperature: 40 C
yield: 72 %

attempt: var2
reaction: @rxn-var2
result: @res-var2
solvent: DMF
temperature: 60 C
yield: 45 %
:::
```

```md
TLC analysis is attached to @cv-screen.var1.
```

The resolver searches `condition_varies.attempts` for the attempt with ID `var1`.

## Template Parameter References

Template expansion supports `@param.name`.

```md
:::template charge_one
params: reagent: ref<molecule> | amount: quantity<amount>
:::procedure #templated
step: charge | id=s-charge | inputs=@param.reagent | amount=@param.amount
:::
:::

:::use charge_one
reagent: mol-acid
amount: 1.0 mmol
:::
```

`@param.reagent` and `@param.amount` resolve only inside template context.

## Inline Chemistry

Inline chemistry uses `:chem[...]`. The content must be non-empty and single-line.

```md
The substrate can be written inline as :chem[Brc1ccccc1].
```

The parser extracts only token data and source positions. Chemical normalization belongs to later service or rendering flows.

## Markdown Link Safety

Markdown links are extracted as `markdown_link` tokens with a `safe` flag. Rendering and security policies can use that flag.

```md
[raw NMR file](data/nmr/var1.pdf)
```
