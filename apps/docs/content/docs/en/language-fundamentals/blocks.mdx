## Common Block Grammar

A structured block starts with `:::block-type` and ends with a standalone `:::`. The opening line can include a header argument, usually an object ID such as `#res-main`.

```md
:::result #res-main
status: success
yield: 76%
:::
```

Object IDs must match `[a-zA-Z][a-zA-Z0-9_-]*`. Invalid IDs produce `E_INVALID_ID`. Nodes without explicit IDs receive generated IDs in the form `<document-id>-<node-type>-<counter>`, but stable references should use explicit IDs.

Field lines use `key: value`. Field keys start with a lowercase letter and then allow lowercase letters, digits, and underscores. Values are trimmed.

```md
solvent: MeCN ;; temperature: 40 C ;; time: 2 h
```

The parser also supports `;;` multi-field lines. Each segment is parsed as a field, while spans still point to the physical line.

List fields use `|` separators. Default list fields are `reactant`, `product`, `reac`, `prod`, `reactants`, `products`, `conditions`, and `params`; `:::chemd` also treats `prev` as a list field. Empty list items produce `E_INVALID_LIST_ITEM`.

Each block parser declares an allowed field set. Unknown fields produce an error-level `W_UNKNOWN_FIELD` diagnostic and are omitted from the parsed node.

Every canonical field also has a shared value category used by docs and
tooling. Current categories include plain text, enum, quantity, percent,
reference or literal, list, record, chemical identifier, and domain-specific
compact syntax. Domain-specific fields such as TLC `spot`, analysis `peak`, and
MS `ion` remain authored compact records until their type-specific normalizers
run later in the pipeline.

Record-shaped fields keep their own parameter schema. For example, reaction
participants have a head value plus `amount`, `equiv`, `mass`, `volume`, and
`limiting` parameters, while `condition-varies` declarations expose `baseline`
and quantity-class parameters.

## Supported Blocks

The body parser currently supports these structured block forms. Most entries are registered block parsers; `:::template` is a parser special-case handled by `parseChildren`.

| Block | AST Type | Purpose |
| --- | --- | --- |
| `:::chemd` | `molecule` or `reaction` | Unified usage surface for molecules and reactions |
| `:::material` | `material` | Purchased or inventory material linked to a molecule |
| `:::batch` | `batch` | Physical batch produced, split, or purified during work |
| `:::result` | `result` | Outcome, yield, purity, and status |
| `:::analysis` | `analysis` | TLC, NMR, HPLC, and other analysis records |
| `:::procedure` | `procedure` | Procedure steps and dependencies |
| `:::trace` | `trace` | Runtime or authored run events |
| `:::observation` | `observation` | Observation events |
| `:::sample` | `sample` | Samples, batches, and lineage |
| `:::artifact` | `artifact` | Files, spectra, images, and external evidence |
| `:::condition-varies` | `condition_varies` | Condition screens and variable comparison |
| `:::template` | `template` | Reusable fragments; parser special-case |
| `:::use` | `use` | Template invocation |
| `:::col` | `col` | Multi-column layout node |

Unknown blocks produce an error-level `W_UNKNOWN_BLOCK` diagnostic.

## `:::chemd`

`:::chemd` is the unified block for molecules and reactions. `kind: molecule` and `kind: reaction` are allowed, including aliases such as `mol` and `reac`, but they are optional when fields make the meaning clear. A block with reaction-shaped fields such as `reactant`, `product`, `reac`, `prod`, `rxn_smiles`, `solvent`, or `temperature` is inferred as a reaction. A block with molecule identity fields such as `smiles`, `inchi`, `inchikey`, `cas`, `formula`, or `role` is inferred as a molecule. Ambiguous or conflicting shapes are errors.

```md
:::chemd #mol-aryl
name: aryl bromide
smiles: Brc1ccccc1
role: substrate
:::

:::chemd #rxn-main
name: Suzuki coupling
reactant: @mol-aryl | 1.0 mmol | 1.0 eq | limiting=true
reactant: @mol-boron | 1.2 eq
product: @mol-product
reagents: K3PO4
catalyst: Pd(PPh3)4
solvent: MeCN
temperature: 40 C
time: 2 h
atmosphere: nitrogen
:::
```

Molecule fields: `smiles`, `canonical_smiles`, `inchi`, `inchikey`, `cas`, `name`, `role`, `caption`, `formula`, `mw`, and `chemistry_features`.

Reaction fields: `reactant`, `product`, `reac`, `prod`, `reactants`, `products`, `rxn_smiles`, `reaction_smiles`, `conditions`, `route`, `prev`, `reagents`, `catalyst`, `solvent`, `temperature`, `time`, `pressure`, `atmosphere`, `yield`, `conversion`, `selectivity`, `caption`, `chemistry_features`.

Validation:

- A molecule requires at least one identity field.
- A reaction requires at least one reactant and at least one product after alias normalization.
- Molecule `amount` and `equivalents` are errors; write reaction usage on participants.

## `:::result`

A result block records the experimental outcome. Both `ref` and `reaction` can carry the reaction association. Use one consistently within a record.

```md
:::result #res-main
ref: @rxn-main
product: @mol-product
status: success
yield: 78%
conversion: 96%
selectivity: 93%
purity: 97%
notes: Best balance of conversion and purity.
:::
```

Fields: `status`, `yield`, `conversion`, `selectivity`, `isolated_mass`, `product_state`, `purity`, `notes`, `ref`, `reaction`, `product`.

## `:::analysis`

An analysis block records instrument or observation-based analysis. The field `type` maps to AST field `type_name`. When `type: tlc` is used, the parser fills default TLC values for missing `plate` and `visualization`.

```md
:::analysis #ana-tlc-main
type: tlc
ref: @rxn-main
time: 2 h
eluent: PE/EA = 4:1
result: one major product spot with trace starting material
data: TLC plate after 2 h.
lane: sm
spot: 0.78 sm
lane: rxn
spot: 0.52 prod
spot: 0.79 sm
lane: prod
spot: 0.50 prod
:::
```

Fields: `type`, `ref`, `time`, `eluent`, `plate`, `visualization`, `result`, `instrument`, `solvent`, `frequency`, `method`, `data`, `notes`, `artifact`, `artifacts`, `spectrum`, `lane`, `spot`, `mess`, `base`, `none`, `peak`, and `ion`.

Resolver required-field validation:

- An analysis requires `type`.
- A TLC analysis can receive `plate` and `visualization` from defaults.

## `:::sample`

A sample block expresses sample identity, lineage, and linked artifacts.

```md
:::sample #sample-product-var1
ref: @res-var1
name: purified product from var1
derived_from: sample-batch-var1
purity: 97%
artifacts: art-nmr-var1
:::
```

Fields: `name`, `sample_id`, `batch`, `purity`, `supplier`, `notes`, `ref`, `derived_from`, `aliquot_of`, `batch_of`, `artifacts`, `chemistry_features`.

Resolver required-field validation: a sample requires `name`.

## `:::artifact`

An artifact block expresses spectra, images, reports, and other evidence files.

```md
:::artifact #art-nmr-var1
kind: nmr_spectrum
ref: @res-var1
path: data/nmr/var1.pdf
checksum: sha256:var1nmr
instrument: Bruker 400
notes: Purified product spectrum.
:::
```

Fields: `kind`, `ref`, `path`, `checksum`, `instrument`, `notes`, `chemistry_features`.

Resolver required-field validation: an artifact requires `kind` and `path`.
