---
title: Natural Language Import
description: CLI, rule sources, and validation boundaries for importing local experiment prose into Chemd drafts.
---

Natural language import turns local experiment prose into a reviewable `.chemd` draft. It is not a new Chemd syntax and it does not bypass the compiler. The importer first extracts material, quantity, step, observation, and reaction candidates, renders existing Chemd block syntax, and then validates the draft through `compileChemd`.

## CLI Usage

```text
pnpm chemd import prose procedure.txt
pnpm chemd import prose procedure.txt --out draft.chemd
pnpm chemd import prose procedure.txt --format json --dry-run
```

Text output prints the generated Chemd draft when `--out` is not provided. With `--out`, the CLI writes only when the generated draft has no compiler errors. `--dry-run` never writes files.

When `RXN_API_KEY` is available in the environment or in a local ignored `.env`
file, the CLI first asks RXN for Chemistry for a paragraph action sequence. If
the request fails or the key is missing, the importer falls back to the local
Chemd procedure lowerer. RXN actions are treated as candidates only: material
names are re-aligned to the original prose, quantities remain subject to Chemd
quantity parsing, and the rendered draft still goes through `compileChemd`.

The JSON schema is `chemd-import-prose/v0.1` and includes:

- `materialCount`, `quantityCount`, `stepCount`, and `observationCount`.
- Severity summaries for import diagnostics and compiler diagnostics.
- The generated `chemd` draft.
- `valid`, `dryRun`, `wroteFile`, and `unparsedSpanCount`.

## Conversion Path

| Stage | Source | Notes |
| --- | --- | --- |
| Material recognition | `@chemd/chemical-lexicon` | Uses the local lexicon, aliases, formula-like recognition, and context confidence by default; it does not call the network by default. |
| Quantity recognition | `@chemd/core` | Uses the Chemd quantity schema and unit normalization; `78%` is a single percent literal, while `78 %` emits a warning. |
| Step recognition | RXN action provider, then `@chemd/step-ontology` fallback | RXN can provide `MAKESOLUTION`, `ADD`, `STIR`, `EXTRACT`, `WASH`, `DRYSOLUTION`, and `PURIFY` action candidates. If unavailable, the local procedure lowerer reuses the StepFamily parameter schema. |
| Observation recognition | `@chemd/step-ontology` | Reuses observation lowering while preserving event type, confidence, and optional linked step. |
| Reaction candidate recognition | material, quantity, and step evidence | Builds a reaction candidate only from high-confidence reaction-stage evidence; explicit product evidence is required before a reaction block is rendered. |
| Reaction rendering | existing Chemd schema and compiler | Renders existing `:::chemd kind: reaction` fields through the current Chemd schema/compiler surface; the importer does not define a separate reaction language. |
| Draft rendering | `@chemd/importer-prose` | Renders existing `:::chemd`, `:::procedure`, and `:::observation` syntax. |
| Final validation | `@chemd/compiler` | The compiler decides whether the draft satisfies the current Chemd language contract. |

This keeps the importer from owning a parallel language rule set. Quantity units, step parameters, reaction fields, and observation events come from existing Chemd packages; when the language layer changes, the importer follows those public APIs.

The RXN layer is deliberately not a trusted fact source. For example, if an RXN
action changes `EtOAc (50 mL x 3)` into `EtOAc (50 mL) 3 x`, Chemd keeps the
original prose as the quantity source and lets the compiler decide whether the
rendered field is valid. `ADD SLN` is treated as a reference to a preceding
`MAKESOLUTION` action instead of a material named `SLN`.

Text that is not covered by a rule is not treated as a high-confidence structured fact. The importer keeps it in `unparsedSpans` and diagnostics; only content recognized as canonical steps is rendered into `:::procedure`, and only high-confidence reaction-stage facts are rendered into `:::chemd kind: reaction`.

For partial matches, the importer reports the gap instead of hiding it. For
example, `washed with brine, dried over Na2SO4, filtered, and concentrated`
can render `wash`, `dry`, and `concentrate`, while the unsupported bare
`filtered` clause remains visible through `W_IMPORT_PROSE_UNCOVERED_ACTION`
and `unparsedSpanCount`.

## Example

English SI input:

```text
To a solution of substrate6 and acyl-silane7 in THF at -78 °C was added sBuLi dropwise. The reaction was stirred for 15 min and afforded azetidine5. H2O was then added to quench the reaction, and the mixture was extracted with EtOAc. The combined organic phases were washed with brine, dried over MgSO4, filtered through Celite, and concentrated under reduced pressure. The residue was purified by flash column chromatography on silica gel using PE/EA 4:1.
```

Generated draft:

```md
---
id: import-procedure
title: Imported procedure
date: 2026-05-23
---

:::chemd #import-reaction-1
kind: reaction
reactant: substrate6 and acyl-silane7
product: azetidine5
reagents: sBuLi
solvent: THF
temperature: -78 °C
time: 15 min
:::

:::procedure #import-procedure
reaction: @import-reaction-1
step: charge | id=s1 | materials=substrate6 and acyl-silane7 | solvent=THF
step: cool | id=s2 | target_temperature=-78 °C
step: add | id=s3 | materials=sBuLi | temperature=-78 °C | mode=dropwise
step: hold | id=s4 | duration=15 min
step: quench | id=s5 | agent=H2O
step: extract | id=s6 | solvent=EtOAc
step: wash | id=s7 | solvent=brine
step: dry | id=s8 | agent=MgSO4
step: filter | id=s9 | medium=Celite
step: concentrate | id=s10 | method=reduced_pressure
step: purify | id=s11 | technique=flash column chromatography | medium=silica gel | eluent=PE/EA 4:1 | column=flash
:::
```

The reaction summary is intentionally narrower than the procedure. `H2O`, `EtOAc`, brine, `MgSO4`, Celite, and flash chromatography stay in the procedure/workup trail and are not written into reaction `reagents` or `solvent`.

## Procedure State Review

The importer also builds a derived procedure state model from the canonical
steps. It is review data, not Chemd syntax and not runtime execution. The model
starts from an empty vessel and records snapshots after each step:

```text
initial: contents=[]
step s1 charge: contents=[substrate6 and acyl-silane7, THF]
step s2 cool: temperature=-78 °C
step s3 add: contents += sBuLi
step s4 hold: duration=15 min
step s5 quench: contents += H2O
step s6 extract: phaseMarkers += extracted
step s7 wash: contents += brine
step s8 dry: contents += MgSO4
step s9 filter: phaseMarkers += filtered
step s10 concentrate: phaseMarkers += concentrated
step s11 purify: phaseMarkers += purified
```

`step:` lines are the authored or imported operations. Procedure state is a
derived review model over those steps. Runtime trace is different again: it is
for live or replayed execution events such as step start, completion, artifacts,
and observations.

If a step family cannot be represented as a state transition, the importer
emits a state warning and keeps the source step or unparsed span visible.

The importer can still create observation-only drafts from prose such as `加入 n-BuLi 后体系逐渐变深红色。`; that path keeps the observation as a reviewable candidate when there is no reaction candidate.

The draft still needs user review. Import-layer `confidence`, formula-like materials, unknown units, excluded workup materials, and parameter drift warnings are review signals, not verified facts.

## Boundaries

- The default path is offline and does not call PubChem, ChemDataExtractor, or external APIs.
- Material recognition starts with the local lexicon and rules; external chemical recognizers can be connected through provider interfaces, but their results must still pass through the same Chemd compiler validation path.
- The importer does not modify the Chemd language layer, add block grammar, or write parser/resolver/typechecker schema.
- Observations are not collapsed into a single block-level fact; events, prose, and step references remain reviewable candidates.
- A reaction block is rendered only when the importer sees an explicit product signal such as `afforded` or `yielded`, because current Chemd reaction drafts need a `product`. Without that signal, the importer emits a warning and still keeps the procedure draft.
- Workup, quench, extraction, drying, and purification materials are excluded from reaction fields and produce warnings instead of being silently written into `reagents` or `solvent`.
