## Condition Screen Model

`:::condition-varies` records a screen as declared factors, declared outcomes, and attempt sections. Declare all `factor:` and `outcome:` lines before the first `attempt:`. Fields after an `attempt:` belong to that attempt until the next `attempt:`.

```md
:::condition-varies #cv-solvent
standard: @rxn-baseline

factor: solvent | baseline=THF
factor: temperature | baseline=25 C
outcome: yield | baseline=68 %
outcome: conversion | baseline=85 %

attempt: mecn-40
reaction: @rxn-mecn-40
result: @res-mecn-40
solvent: MeCN
temperature: 40 C
yield: 72 %
conversion: 90 %
note: clean conversion by TLC
:::
```

`standard` points to the baseline reaction. A factor without an attempt value inherits its baseline. A declared outcome must be present in every attempt.

## Factors and Outcomes

`factor:` names inputs or controlled variables. `outcome:` names measured outputs such as `yield`, `conversion`, `ee`, or purity. Names must be declared once, cannot overlap, and cannot use reserved section fields such as `standard`, `factor`, `outcome`, `attempt`, `reaction`, `result`, `note`, or `notes`.

```md
factor: solvent | baseline=THF
factor: catalyst | baseline=Pd(PPh3)4
outcome: yield | baseline=68 %
outcome: ee | baseline=92 %
```

The baseline on an outcome describes the standard result. If Chemd can infer the standard result and the declared baseline conflicts with that result, validation reports an error rather than guessing.

## Attempts

Each `attempt:` opens one attempt. Use stable attempt IDs because references such as `@cv-solvent.mecn-40` resolve through the attempt ID.

```md
attempt: dmf-60
reaction: @rxn-dmf-60
result: @res-dmf-60
solvent: DMF
temperature: 60 C
yield: 45 %
conversion: 70 %
```

`result:` is optional, but when present it must reference a result block. Attempt outcome values must not conflict with the linked result fields.

## Organizing Reactions and Results

Declare baseline and attempt reactions as normal `:::chemd` reaction objects. Store rich result data in `:::result`, then link that result from the attempt.

```md
:::result #res-mecn-40
reaction: @rxn-mecn-40
product: @product
status: success
yield: 72 %
conversion: 90 %
:::

:::condition-varies #cv-oxidation
standard: @rxn-baseline
factor: solvent | baseline=THF
outcome: yield | baseline=68 %

attempt: mecn-40
reaction: @rxn-mecn-40
result: @res-mecn-40
solvent: MeCN
yield: 72 %
:::
```

This keeps the screen table compact while preserving reaction and result objects for graph, export, and validation.

## Diagnostics

Chemd treats ambiguous or meaning-changing screen data as errors. Duplicate declarations, reserved names, declarations after attempts, missing attempt IDs, unknown attempt fields, duplicate attempt values, missing outcomes, and conflicts with linked result fields all produce errors.
