## One-Step Synthesis Record

A one-step synthesis typically contains reagent molecules, product molecule, main reaction, main result, procedure, analysis, sample, and artifact. `best-practice-one-step-synthesis.chemd` shows this combination.

```md
---
id: one-step-example
title: One-step oxidation record
date: 2026-05-19
primary_reaction: rxn-main
primary_result: res-main
---

:::chemd #substrate
kind: molecule
smiles: CCO
name: ethanol
:::

:::chemd #product
kind: molecule
smiles: CC=O
name: acetaldehyde
:::

:::chemd #rxn-main
kind: reaction
reactants: substrate
products: product
solvent: DCM
temperature: 0 C
time: 2 h
:::

:::result #res-main
ref: rxn-main
status: success
yield: 62 %
:::

:::procedure #proc-main
reaction: rxn-main
step: add | id=s-add-oxidant | reagent=oxidant | temperature=0 C | mode=dropwise
step: hold | id=s-hold | duration=2 h | dependsOn=s-add-oxidant
step: quench | id=s-quench | reagent=sodium sulfite | dependsOn=s-hold
:::
```

A stable minimal record should declare explicit object IDs and use `primary_reaction` and `primary_result` for the main reaction and result.

## Total Synthesis Route Steps

The total synthesis fixture uses multiple reactions and expresses route relationships through `route` and `prev`. Each step keeps its own result and procedure, enabling graph export to infer route edges.

```md
:::chemd #rxn-step-1
kind: reaction
reactants: starting-material
products: intermediate-1
route: route-a
:::

:::chemd #rxn-step-2
kind: reaction
reactants: intermediate-1
products: final-product
route: route-a
prev: rxn-step-1
:::

:::result #res-step-2
ref: rxn-step-2
status: success
yield: 48 %
:::
```

`route` stores the route name and `prev` stores the upstream reaction ID. Keep each route step as a separate reaction and result node.

## Condition Screen Record

A condition screen should contain a baseline reaction, attempt reactions, attempt results, and `condition-varies`. `varN` connects the attempt reaction, and `resN` connects the attempt result.

```md
:::condition-varies #cv-base
standard: rxn-baseline
condition: solvent=THF | temperature=25 C
varies: solvent | temperature
var1: id=attempt-mecn-40 | reaction=rxn-mecn-40 | solvent=MeCN | temperature=40 C
res1: res-mecn-40
note1: highest conversion in the first screen
:::
```

The screen table should preserve baseline conditions and declared dimensions. Use separate `:::result` blocks when attempt outcomes include yield, conversion, selectivity, and purity.

## Analysis-Driven Record

Analysis-driven records connect `:::analysis` to a reaction, result, or condition attempt. TLC uses `pN` lanes. HPLC and NMR use `instrument`, `method`, `result`, and `data`.

```md
:::analysis #ana-tlc-screen
type: tlc
ref: cv-base.attempt-mecn-40
eluent: petroleum ether/ethyl acetate 4:1
p1: sm rf=0.20 ^ (2)
p2: product rf=0.55 v (4)
result: product spot dominant after 2 h
:::

:::analysis #ana-hplc-product
type: hplc
ref: res-main
instrument: Agilent 1260 Infinity II
method: C18 gradient 10-90% MeCN
data: reports/hplc/main-product.pdf
result: purity 96 %
:::
```

TLC lanes parse labels, `rf`, direction markers, and intensity markers into structured lane items. HPLC, NMR, LCMS, and related methods use generic analysis fields.

## Sample Tracking Record

Sample tracking uses `derived_from`, `aliquot_of`, and `batch_of` for lineage. `artifacts` connects spectra, images, and reports.

```md
:::sample #sample-crude
ref: rxn-main
name: Crude reaction mixture
batch: batch-main
:::

:::sample #sample-purified
ref: res-main
name: Purified main product
derived_from: sample-crude
batch_of: batch-main
artifacts: art-nmr-1h | art-hplc-report
:::
```

Stable IDs are the core of sample tracking. `derived_from` records preparation lineage, `batch_of` records batch membership, and `artifacts` records evidence files.

## Artifact Evidence Record

Artifact evidence uses `kind`, `ref`, `path`, optional `checksum`, and optional `instrument`. Place NMR, TLC, LCMS, image, and report files at the end of evidence chains so they remain traceable to samples, analyses, or results.

```md
:::artifact #art-nmr-1h
kind: nmr
ref: sample-purified
path: data/nmr/product-1h.jdx
checksum: sha256:9c8a7f1e
instrument: Bruker Avance 400
notes: 1H NMR in CDCl3
:::
```

Artifacts store evidence metadata. Analytical interpretation belongs in `:::analysis`; file paths and acquisition devices belong in `:::artifact`.

## Multi-Document Route Organization

`pnpm chemd graph <file...>` compiles multiple documents and builds a graph index from training understandings. Multi-document routes should keep stable document IDs, explicit reaction IDs, and consistent route names.

```md
---
id: route-a-step-2
title: Route A step 2
date: 2026-05-19
primary_reaction: rxn-route-a-step-2
---

:::chemd #rxn-route-a-step-2
kind: reaction
reactants: intermediate-1
products: final-product
route: route-a
prev: route-a-step-1#rxn-route-a-step-1
:::
```

The typechecker supports scoped IDs in the form `documentId#objectId`. Cross-source routes should use stable document IDs and object IDs for graph-index aggregation.

## Best Practice Example

Start with the smallest complete record that satisfies validation, then add analysis, sample, artifact, route, and screening structures as the experiment requires.

```md
---
id: exp-pattern-minimal
title: Minimal complete pattern
date: 2026-05-19
primary_reaction: rxn-main
primary_result: res-main
---

:::chemd #mol-start
kind: molecule
smiles: CCO
:::

:::chemd #mol-product
kind: molecule
smiles: CC=O
:::

:::chemd #rxn-main
kind: reaction
reactants: @mol-start
products: @mol-product
:::

:::result #res-main
reaction: rxn-main
product: mol-product
status: success
yield: 70%
:::
```
